## Подготовка и запуск

Прочитайте [инструкцию среды](../../environment/README.md). Используются прежние закреплённые JDK 25, PostgreSQL 18.6 и pgJDBC; новых зависимостей нет. Нужны Docker и Compose, редактор и доступ к загрузке образов при первом запуске. Maven, Gradle, локальные Java и PostgreSQL не нужны.

Из корня репозитория перед **каждым самостоятельным сценарием**:

```text
docker compose up -d --wait db
docker compose exec -T db psql -X -U plm_owner -d plm -v ON_ERROR_STOP=1 -f /workspace/practice/postgresql/schema/reset.sql
docker compose build java
```

Reset атомарно пересоздаёт `lab`, включая дополнительные [таблицы Java](schema.sql). Исходные изделия, BASE-01 и L01–L14 сохраняют свои исходные данные; `java_*` — отдельные учебные структуры. Для J09 намеренно используется общая `installation`, поэтому следующий сценарий тоже начинается с reset. Файлы output reset не удаляет.

Пример своей попытки и эталона:

```text
docker compose run --rm java practice/java/advanced/QuantityService.java
docker compose run --rm java practice/solutions/java/QuantityService.java
```

Каждое задание ниже содержит точные аргументы. Эталон открывайте после попытки и отдельного reset. Ненулевой код и `UnsupportedOperationException` с сообщением «Реализуйте методы по контракту задания…» у заготовки ожидаемы. Заготовка должна компилироваться, но ещё не решает задачу. JDK автоматически компилирует необходимые соседние исходники в source-file mode; [Lab.java](Lab.java) содержит готовые соединения, транзакции и параметры SQL. При копировании заготовки сохраните рядом Lab.java; OutboxWorker также использует соседний OrderedConsumer. Файлы `.class` на хосте не нужны.

Альтернативы `docker compose run --rm java ...`: `powershell -NoProfile -ExecutionPolicy Bypass -File practice/environment/lab.ps1 java ...` и `bash practice/environment/lab.sh java ...`. Для SQL-файлов используйте команду `sql practice/java/advanced/имя.sql` тех же обёрток. PowerShell-команды работают из корня, Bash — из корня в Linux/WSL. Не передавайте SQL через текстовый конвейер PowerShell.

## Как проходить глубже

Сначала разберите контракт и ожидаемые состояния на бумаге. Затем реализуйте метод с TODO, выполните нормальный сценарий, граничный случай и отказ. После отказа исследуйте БД отдельным соединением: отсутствие сообщения об успехе само по себе не доказывает rollback. Сравните своё решение с эталоном и объясните, какие гарантии требуют участия всех писателей.

Порядок J01 → J02 → J03 → J04 даёт модель данных; J05 → J06 → J07 — транзакционные протоколы; J08 → J09 → J10 — производственный и физический контекст; J11 → J12 — файлы и аналитический вывод. По данным задания независимы. J04 использует готовые OLD/NEW, J07 может использовать готовый OrderedConsumer из каталога эталонов как инфраструктуру, J12 — готовый OLD. Выполнение J03/J05/J06 не является скрытым предусловием.

Дополнительные исследования в заданиях требуют своего расширения кода; они явно отделены от реализованного контракта эталона. Нет скрытых тестов, запускающего проверку решений скрипта или автоматического оценивания. [Протокол автора](../../environment/verification.md) относится к работоспособности опубликованных материалов.

## Язык исходников

Пояснения, комментарии, подсказки запуска и свободный текст сообщений написаны по-русски. Идентификаторы Java и SQL, названия API, имена полей и файлов, параметры fail/crash и машинные коды вроде APPLIED или VERSION_GAP_OR_STALE сохраняются для согласованности контрактов. Это технические обозначения; их смысл объяснён в заданиях и эталонах.

## Границы стенда

Это учебные сервисы с CLI, не коммерческие API и не production framework. `Connection` не передаётся между потоками. Строковый payload событий сравнивается побайтно на уровне Java String, семантическая эквивалентность JSON не обещана. Полноценный JSON-парсер не пишется и JSON-контракт не заявляется. Получатель размещён в той же БД, но имеет отдельные таблицы и транзакции; сетевые протоколы отсутствуют. В J07 вручную воспроизводится разрыв между фиксацией эффекта и квитанцией отправителя.

Снимки защищены учебным протоколом и триггерами от UPDATE/DELETE и дописывания строк после seal; владелец БД может обойти защиту. Полной модели прав записи здесь нет. Политики RLS, реальные файлы CAD/CAM/CAE, брокер, HTTP-сервер, MRP и отраслевые нормы не добавляются неявно.

Уборка выполняется прежней командой `clean` из инструкции среды; сначала сохраните свои нужные результаты. Она удаляет output и данные только выбранного Compose-проекта. Для двух терминалов конкурентного сценария Compose-имя должно совпадать.
