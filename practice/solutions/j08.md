# J08. Разбор маршрута

[К заданию](../exercises/j08-java-routing/README.md) · [К эталонам](README.md) · [Исходник](java/RoutePlanner.java)

После reset `docker compose run --rm java practice/solutions/java/RoutePlanner.java ROUTE-A` выдаёт семь волн и BLOCKED_RESOURCE OP40 COAT. Это корректный порядок с неготовым ресурсом, а не разрешение производства. После j08-cycle.sql алгоритм отказывает.

Все операции выбранного маршрута сначала включаются в Map; нулевые степени создаются даже для изолированных операций. Затем читаются рёбра. Если только один конец принадлежит маршруту, возникает CROSS_ROUTE_DEPENDENCY: иначе «красивый» план был бы получен потерей обязательной предпосылки.

Алгоритм Кана берёт весь текущий набор нулевой степени одной волной. Новые нулевые вершины относятся к следующей волне, даже если их id меньше прочих. TreeSet делает вывод воспроизводимым. Цикл означает, что число обработанных вершин меньше числа операций; необработанные включают также зависимые вершины, поэтому сообщение не объявляет их всех участниками цикла.

После изменения связей из задания возникает WAVE OP50,OP60, а OP70 ждёт обе операции. Допустимая по графу параллельность не говорит, что хватает общих ресурсов, квалификаций и входов. Ресурс отдельно сверяется по qualified и family. Даже qualified=true не разрешает ресурс другого семейства.

Эталон не рассчитывает расписание, длительности, загрузку оборудования или материальный баланс. Allocation остаётся отдельной учебной моделью. Сильно связные компоненты, альтернативные ветви и интервальные квалификации из задания требуют дальнейшей реализации. При самооценке объясняйте, какую гарантию даёт каждая часть плана.
