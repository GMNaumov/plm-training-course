# J11. Разбор манифеста и ограниченного параллелизма

[К заданию](../exercises/j11-java-files/README.md) · [К эталонам](README.md) · [Исходник](java/FileProvenance.java)

После reset `docker compose run --rm java practice/solutions/java/FileProvenance.java FILES-1` выводит три записи. housing.txt и housing-copy.txt имеют одинаковый SHA-256, но сохраняют разные role/tool_version. Повтор runId даёт конфликт ключа; идемпотентность запуска в этом контракте не заявлена.

Манифест читается в REPEATABLE READ в неизменяемый список Job с пределом 1000. Затем читающая транзакция закрывается. Виртуальные потоки выполняют только файловую работу; JDBC Connection между ними не передаётся. Semaphore берётся до submit, поэтому ограничивает одновременно выданную работу, а не только операции после создания множества ожидающих потоков. Внутри каждой задачи разрешение освобождается в finally.

SHA-256 обновляется буфером 8192 байта. Относительный путь разрешается через toRealPath, проверяется принадлежность разрешённому корню. Реальные пути учитывают symlink; отсутствие конкурентной подмены обеспечено учебным read-only источником, не переносится автоматически на произвольный изменяемый каталог.

Future читаются в порядке исходного списка, поэтому отчёт стабилен при другом порядке завершения. Любое исключение отменяет оставшиеся задачи; стандартное закрытие executor ждёт их завершения. Interrupt не гарантирует мгновенное прерывание любого I/O. После успешного вычисления всех digest одна новая транзакция вставляет полный run; при ошибке БД частичный run тоже откатывается.

Недостающий файл и путь ../seed.sql не создают строк результата. Совпадение хеша означает совпадение байтов, а не равенство документов или актуальность представления. Версия инструмента сохранена как происхождение, но настоящий преобразователь не запускается. Модель не проверяет геометрию, расчётную пригодность или реальный CAD API.
