# Эталон L04. Единицы, неизвестные значения и свойства

[Постановка, условия и самопроверка](../exercises/l04-reference/README.md) · [Все эталоны](README.md)

## Решение и основания

Фактор задаётся относительно базовой единицы своей размерности. Поэтому factor для mm нельзя применять к свойству массы. Сначала проверяется размерность, затем преобразование, затем статус значения.

В эталоне таблица mass_property показывает ограничения состояния, но допустимость размерности остаётся явной границей модели. Для усиления схемы можно создать mass_unit(code FK unit) и ссылаться на неё; пополнение этого списка становится управляемой операцией. Неизвестное значение и неприменимое свойство допускают NULL по разным основаниям. Похожее название изделия не даёт основания объединять его с другим каталогом.

## Ожидаемый результат

HO-A: OK и 2.5 kg; RO-A: OK и 1.2 kg; SEN-A: UNKNOWN и NULL; HAR-A: DIMENSION_MISMATCH и NULL. В таблице свойств нет ложного нуля и ложной массы жгута. Проверки статуса не допускают known с NULL и unknown с числом. Объяснено, что FK на unit подтверждает существование единицы, но не её допустимость для массы.

## Усиление ограничения размерности

Один вариант дополнительного DDL после основного решения:

```sql
CREATE TABLE lab.mass_unit(code text PRIMARY KEY REFERENCES lab.unit);
INSERT INTO lab.mass_unit VALUES ('kg'),('g');
ALTER TABLE lab.mass_property ADD FOREIGN KEY(unit) REFERENCES lab.mass_unit;
```

Так mm отклоняется уже FK. Правило наполнения mass_unit должно дополнительно проверять dimension='mass'; перенос этого списка в управляемые НСИ остаётся ответственностью владельца модели. Для маленького закрытого набора возможен CHECK(unit IN ('kg','g')), но он требует DDL при расширении единиц.
