# J07. Разбор аренды доставки

[К заданию](../exercises/j07-java-outbox/README.md) · [К эталонам](README.md) · [Исходник](java/OutboxWorker.java)

После reset вызов `docker compose run --rm java practice/solutions/java/OutboxWorker.java crash` применяет EVT-1 у получателя и падает до подтверждения отправителя. Следующие вызовы без crash обслужат второе событие и повторно EVT-1 после истечения десятисекундной аренды. Итоговый повтор у получателя — REPLAY:APPLIED; затем очередь даёт IDLE.

Claim удерживает блокировку только на java_delivery. JOIN с неизменяемым по протоколу java_outbox даёт договор события; SKIP LOCKED пропускает уже занятые строки. UUID создаёт уникальное владение попыткой, lease_until вычисляется по часам БД. После commit claim блокировки сняты, поэтому длительность вызова получателя не удерживает транзакцию отправителя.

Получатель J06 фиксирует эффект и квитанцию в своей транзакции. Между этим commit и ack отправителя нет общей атомарности. Именно поэтому crash не должен означать «получатель не применил». Повтор того же eventId находит прежнюю квитанцию и разрешает подтвердить доставку без второго эффекта.

Acknowledge проверяет token, delivered=false и неистёкшую аренду. Если прежний работник проснулся после повторной выдачи, его token уже не подходит. Даже без нового работника истёкшая аренда не даёт права подтвердить текущую попытку. UUID здесь не монотонный счётчик; защита обеспечивается условием UPDATE в БД.

Для сценария stale token сохраните старый Claim, дайте ему истечь, получите новый и вызовите acknowledge со старым: false. Два работника после reset могут независимо взять разные события. Порядок по агрегату не обеспечен: N+1 может быть выдано раньше N, получатель вернёт gap, аренда позволит повторить позднее. Backoff, dead-letter и продление аренды остаются дополнительными исследованиями.

Эталон использует тот же сервер PostgreSQL ради малого стенда, но три разные транзакции и отдельные таблицы отправителя/получателя. Вызов Java не воспроизводит сетевую задержку или HTTP-статусы. Он показывает предметную неопределённость между фиксацией эффекта и подтверждением доставки.
