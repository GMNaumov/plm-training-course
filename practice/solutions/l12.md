# Эталон L12. Фактическая история и границы знания

[Постановка, условия и самопроверка](../exercises/l12-physical/README.md) · [Все эталоны](README.md)

## Решение и основания

Текущая таблица installation хранит начало регистрации установки, но не историю последующего редактирования её окончания. Поэтому фильтр recorded_at≤дата знания отбрасывает I-2, а уже изменённый effective_to скрывает I-1: получится ложный пробел.

Сохранение событий закрытия позволило бы воспроизводить состояние на дату знания. Альтернатива — версия отношения с периодами фактической и регистрационной действительности. Обе модели требуют правил исправлений. Учебная партия связывается с компонентами напрямую и не моделирует полную количественную генеалогию преобразования материалов; анализ выделяет популяцию, а не выдаёт заключение качества.

## Ожидаемый результат

На 11 августа по сегодняшним данным: позиция 30 → S-002, 50 → EC-001. Достоверный ответ «что знала система 11-го» невозможен: нет истории внесения effective_to у I-1. По LOT-1 кандидат DM-100 встречается один раз. EC-001/ECU-A с FW-A совместимы по учебной таблице; пересечений установок нет. Неполный результат обозначен явно.

## Воспроизведение

[Эталонный SQL](l12.sql)

Сначала верните исходные данные действием reset. Затем выполните SQL командой `sql practice/solutions/l12.sql` через lab.ps1 или lab.sh по инструкции задания. SQL содержит демонстрацию успешных операций; ожидаемые отказы изучаются отдельно, чтобы не прерывать файл при ON_ERROR_STOP. Точная последовательность и параметры приведены в постановке.

Это одно обоснованное решение. Иная схема или запрос допустимы при сохранении предметных инвариантов и диагностик. Эталон не является промышленным модулем коммерческой PLM-системы.
