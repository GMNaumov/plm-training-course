# Эталон L14. Python и SQL: перенос с происхождением

## Решение и основания

Нормализация отделена от загрузки. Decimal сохраняет десятичный смысл; is_finite проверяется до сравнения, поскольку NaN не является обычным числом. S1 и S5 дают один HO-X с одинаковой массой, но два соответствия происхождения.

Принятые CSV сначала загружаются в TEMP-таблицу. Проверка сравнивает всё содержание повторного source_id, включая правило и оригинал, а не только итоговую массу. Затем записываются staging, цель и mapping в одной транзакции. Несогласованное изменение исходника требует новой управляемой стратегии переноса, а не ON CONFLICT DO UPDATE без анализа. Исключения остаются в rejected.csv и входят в знаменатель полноты. Эталон рассчитан на последовательный запуск одного загрузчика; параллельные загрузки потребуют общей стратегии блокировок.

## Ожидаемый результат

Приняты S1, S2, S5: массы 2.5, 1.2, 2.5 kg. Отклонены S3 (неизвестная масса), S4 (единица длины), S6 (отрицательная), S7 (NaN). Итог: 3 исходные принятые строки, 2 целевых изделия, 3 mapping, 4 исключения; 3+4=7. Повтор не меняет числа. Изменённый source_id или конфликтующая масса атомарно отклоняются. Original сохраняет исходные пробелы, число и единицу.

## Воспроизведение

[Эталонный SQL](l14.sql) · [Эталон Python](migrate.py)

Сначала верните исходные данные действием reset. Затем выполните SQL командой `sql practice/solutions/l14.sql` через lab.ps1 или lab.sh по инструкции задания. SQL содержит демонстрацию успешных операций; ожидаемые отказы изучаются отдельно, чтобы не прерывать файл при ON_ERROR_STOP. Перед SQL обязательно сформируйте CSV запуском practice/solutions/migrate.py; повтор SQL исследуется без reset. Точная последовательность и параметры приведены в постановке.

Это одно обоснованное решение. Иная схема или запрос допустимы при сохранении предметных инвариантов и диагностик. Эталон не является промышленным модулем коммерческой PLM-системы.

## Ручной конфликт и откат

После успешного импорта повтор того же SQL выводит INSERT 0 0 для трёх постоянных таблиц, итог 3/2/3. Для исследования измените mass_kg у S1 в сгенерированном accepted.csv с 2.5 на 2.6, оставив source_id. Повтор импорта останавливается на исключении «Ключ источника повторно использован с другим содержимым». Сессия файла закрывается, незавершённая транзакция откатывается; в постоянных таблицах остаются прежние 3/2/3 и HO-X=2.5.

После проверки заново запустите эталон Python: CSV восстановится из неизменённого legacy.csv. Для отдельного исследования конфликта целевого кода можно добавить новый source_id с HO-X и иной массой: он должен быть отклонён проверкой «Противоречащие значения массы одного изделия».
