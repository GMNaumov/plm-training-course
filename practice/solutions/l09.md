# Эталон L09. Изменение: согласовано и внедрено

[Постановка, условия и самопроверка](../exercises/l09-change/README.md) · [Все эталоны](README.md)

## Решение и основания

Версия защищает от перезаписи изменившегося объекта, а блокировка родителя задаёт место сериализации изменения и его действий. Это совместный протокол: если другой писатель изменит child без блокировки родителя, гарантия будет нарушена.

SQL здесь выполняется владельцем стенда и показывает модель транзакции. В реальном сервисе переход должен также проверить полномочия, полноту области и свидетельства внедрения. Условное подтверждение не является фактом работы площадки. Повтор с устаревшей версией не признаётся автоматически успешной идемпотентной операцией: для этого нужен отдельный ключ команды и сохранённый результат.

## Ожидаемый результат

До подтверждения P1 переход меняет 0 строк; после — одну. Итог CH-1: implemented, lock_version=1. Повтор с версией 0 меняет 0 строк. ACT-3 остаётся excluded с основанием. Никакие установки, BASE-01 и старые свидетельства не переписаны. В отчёте назван общий протокол блокировки родителя для всех писателей действий.

## Воспроизведение

[Эталонный SQL](l09.sql)

Сначала верните исходные данные действием reset. Затем выполните SQL командой `sql practice/solutions/l09.sql` через lab.ps1 или lab.sh по инструкции задания. SQL содержит демонстрацию успешных операций; ожидаемые отказы изучаются отдельно, чтобы не прерывать файл при ON_ERROR_STOP. Точная последовательность и параметры приведены в постановке.

Это одно обоснованное решение. Иная схема или запрос допустимы при сохранении предметных инвариантов и диагностик. Эталон не является промышленным модулем коммерческой PLM-системы.

## Две сессии и протокол

В первой сессии `BEGIN; SELECT id FROM lab.change_order WHERE id='CH-1' FOR UPDATE;`, оставьте транзакцию открытой. Во второй выполните такой же блок: получение родительской блокировки ожидает первую сессию. После COMMIT или ROLLBACK в первой продолжит вторая. Во второй повторно проверяются версия и действия; завершите её ROLLBACK, если это только опыт.

Блокировка родителя не блокирует любой произвольный UPDATE change_action автоматически. Общий протокол обязателен для всех сервисных писателей; суперпользователь SQL-стенда может его обойти. Поэтому этот пример не доказывает защищённость от неконтролируемых прямых изменений.
