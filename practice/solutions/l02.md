# Эталон L02. Доступ и неполный результат

[Постановка, условия и самопроверка](../exercises/l02-access/README.md) · [Все эталоны](README.md)

## Решение и основания

Сначала требуется USAGE схемы, затем SELECT нужных таблиц; наличие политики не выдаёт табличного права. RLS применяется к revision, а не автоматически ко всем связанным таблицам. Item остаются видимыми: политика упражнения разрешает каталог идентичностей независимо от наличия видимой ревизии.

Владелец стенда — суперпользователь. Он обходит RLS, поэтому проверка проводится именно после SET ROLE. NOLOGIN выбран для моделирования полномочий без создания сетевого пользователя. Это не проверка аутентификации, изоляции арендаторов или промышленная модель безопасности.

## Ожидаемый результат

Под lab_reader видны 11 выпущенных ревизий; HO-C и FW-B скрыты. UPDATE и чтение occurrence отклонены. Владелец видит 13 ревизий. Роль не получила DDL и записи. В выводе отражено, что разрешённый список не доказывает полноту инженерной конфигурации.

Это одно обоснованное решение. Иная схема или запрос допустимы при сохранении предметных инвариантов и диагностик. Эталон не является промышленным модулем коммерческой PLM-системы.

## Ручная проверка запретов

В интерактивном psql после основного решения:

```sql
SET ROLE lab_reader;
SELECT count(*) FROM lab.revision; -- 11
UPDATE lab.revision SET state='draft' WHERE id='HO-A'; -- permission denied
SELECT * FROM lab.occurrence; -- permission denied
RESET ROLE;
```

Это отдельные операторы в autocommit. Если их обернуть в BEGIN, после первого отказа нужен ROLLBACK, прежде чем продолжать.
