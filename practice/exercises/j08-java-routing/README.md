# J08. Граф маршрута, параллельные волны и готовность ресурсов

[Все задания](../README.md) · [Java-ветка](../../java/advanced/README.md) · [Теория](../../../course/14-process-and-routing/theory.md) · [Глоссарий](../../../references/glossary.md)

## Задача и предварительные условия

Прочитайте L11. Нужны графы, степени входа, коллекции и JDBC. Реализуйте объяснимую топологическую раскладку маршрута, сохраняя различие между допустимой последовательностью и готовностью производства.

После reset ROUTE-A содержит заготовку, мехобработку, термообработку, покрытие, сборку, электромонтаж и контроль/испытания. В учебном справочнике qualified=false у COAT. Реальные технологические режимы не заданы.

## Реализация

В [RoutePlanner.java](../../java/advanced/RoutePlanner.java) реализуйте `plan`:

1. Прочитайте операции выбранного маршрута и ресурсы в REPEATABLE READ. Неизвестный или пустой маршрут диагностируйте, а не объявляйте готовым.
2. Для всех связей precedence с одним концом в маршруте проверьте второй конец. Внешняя зависимость не должна тихо исчезнуть из-за INNER JOIN по двум выбранным операциям.
3. Алгоритмом Кана вычислите волны нулевой входной степени. Все операции волны предшествуют добавленным операциям следующей; порядок внутри волны стабилизируйте по id.
4. Если обработаны не все операции, сообщите CYCLE_OR_DEPENDENTS_OF_CYCLE. Остаток алгоритма включает зависимые от цикла вершины: он не является точным списком участников цикла.
5. Отдельно выведите BLOCKED_RESOURCE для неквалифицированного ресурса или несовпадения его семейства с операцией. Отсутствие цикла не снимает такой блокировки.

```text
docker compose run --rm java practice/java/advanced/RoutePlanner.java ROUTE-A
```

## Сценарии

Исходно семь последовательных волн OP10…OP70 и BLOCKED_RESOURCE OP40 COAT. Отчёт не является разрешением запуска. После отдельного reset добавьте цикл:

```text
docker compose exec -T db psql -X -U plm_owner -d plm -v ON_ERROR_STOP=1 -f /workspace/practice/java/advanced/j08-cycle.sql
docker compose run --rm java practice/java/advanced/RoutePlanner.java ROUTE-A
```

Ожидается отказ. Для сценария параллельности после нового reset измените связи через psql:

```sql
DELETE FROM lab.precedence WHERE before_id='OP50' AND after_id='OP60';
INSERT INTO lab.precedence VALUES ('OP40','OP60'),('OP50','OP70');
```

Теперь OP50 и OP60 образуют общую волну, OP70 ждёт обе. Это синтетическая альтернативная последовательность для алгоритма, без утверждения инженерной пригодности. Внешнюю зависимость исследуйте отдельной операцией другого route и ребром к ROUTE-A: ожидайте CROSS_ROUTE_DEPENDENCY.

## Самооценка и углубление

Вы можете объяснить входную степень каждой операции и почему ресурс проверяется после анализа порядка. Распределение материалов, фактическая доступность, инструкции, результаты контроля и квалификация с интервалом действия остаются отдельными вопросами. Значение qualified — сокращённая модель, не аттестационная процедура.

Дополнительно выделите сильно связные компоненты для точной диагностики циклов. Затем введите альтернативные процессы с выбором одной ветви до сортировки; затем интервальные подтверждения ресурса в контексте площадки и даты. Не складывайте альтернативные ветви в один обязательный граф.
