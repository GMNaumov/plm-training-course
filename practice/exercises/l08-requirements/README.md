# L08. Требования и действительные свидетельства

[Каталог заданий](../README.md) · [Глоссарий](../../../references/glossary.md)

## Постановка задачи

Менеджер требований получил отчёт «все требования с проверками покрыты». Проверьте его предметный смысл. В данных есть положительная проверка старого корпуса и документ не той ревизии.

1. Выведите все requirement, сохранив требования без evidence. Признать подтверждение можно только при result=pass, точном совпадении tested_revision с target_revision, released-документе и совпадении document.source_revision с целью.
2. Покажите для каждой существующей связи причину непригодности. Не считайте число evidence числом подтверждённых требований и не теряйте REQ-3 при INNER JOIN.
3. Получены два условных решения владельца: одобренный протокол HO-B и одобренный протокол SEN-A. Добавьте новые документные объекты и свидетельства, не исправляя историю EV-1…EV-3 задним числом. Повторите отчёт.
4. Объясните, почему URI, статус released и pass в учебной БД ещё не доказывают качество реального испытания. Сформулируйте границу полноты этого отчёта и владельца решения по непокрытому требованию жгута.

## Предварительные условия

Прочитайте [теорию темы 11](../../../course/11-requirements-management/theory.md) и связанные подтемы ниже. Уровень: уверенный SQL. Поднимите [контейнерную среду](../../environment/README.md).

Перед началом выполните `reset`: это возвращает общую исходную базу ДМ-01 и удаляет результаты предыдущего задания в схеме lab. Все практикумы независимы по данным; проходите их в порядке номеров для последовательного освоения. Не выполняйте reset посреди практикума. Файлы в practice/output reset не удаляет.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File practice/environment/lab.ps1 reset
```

Команды в заданиях выполняются из корня репозитория. Для Ubuntu: `bash practice/environment/lab.sh reset`. Редактируйте заготовку на хосте любым редактором; SQL и код исполняйте в контейнерах.

## Критерии самостоятельной оценки

До исправления ни одно из трёх требований не подтверждено. REQ-1 имеет старую ревизию и pending новой; REQ-2 ссылается на документ HO-A; REQ-3 не имеет свидетельств. После добавления EV-4 и EV-5 подтверждены REQ-1 и REQ-2, REQ-3 остаётся неподтверждённым. Старые свидетельства сохранены.

Сохраните собственный SQL/код, результаты и краткое объяснение оснований решения. Сравнивайте предметный смысл, точные ключи, количества и отказы; порядок строк без ORDER BY и времена выполнения могут отличаться. Автоматического оценивания, баллов и обязательной сдачи нет.
