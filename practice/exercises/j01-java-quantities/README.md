# J01. Типизированные количества и неизвестные данные

[Все задания](../README.md) · [Java-ветка и запуск](../../java/advanced/README.md) · [Теория НСИ](../../../course/05-master-and-reference-data/theory.md) · [Глоссарий](../../../references/glossary.md)

## Задача и предварительные условия

Прочитайте тему 05 и L04. Достаточно понимать JDBC, record и десятичные числа. На ДМ-01 масса известна не для каждого документа; неизвестное нельзя заменить нулём. Реализуйте сервис нормализации измерений в килограммы, который возвращает типизированный результат, а не только число.

Выполните общий reset по инструкции Java-ветки. Таблица `java_measurement` содержит семь независимых строк M1–M7; справочник `unit` хранит размерность и множитель перехода в базовую единицу. Поле `raw_value` оставлено текстом для демонстрации некорректного входа.

## Контракт

`convert(raw, dimension, factor)` возвращает `Result(status, kilograms)`. NULL означает UNKNOWN; известная единица другой размерности — DIMENSION_MISMATCH; некорректное либо неположительное значение — INVALID. Только KNOWN содержит число. Проверка неизвестности выполняется первой. При успешном чтении справочника множитель положителен; повреждение самого справочника требует отдельной диагностики, а не результата KNOWN.

Учебная грамматика числа: не более 80 символов, цифры и необязательная дробная часть через точку. Пробелы, экспонента, запятая, NaN, Infinity, знак минуса и ноль отвергаются. Это явный договор входа, не предел возможностей BigDecimal. Точность пересчёта сохраняется без double и промежуточного округления.

## Реализация

1. В [QuantityService.java](../../java/advanced/QuantityService.java) заполните `convert`. Объясните, почему проверка NULL идёт раньше построения BigDecimal.
2. Оставьте исходную строку в отчёте при любой ошибке. Готовый JDBC-запрос использует LEFT JOIN; замените его мысленно на INNER JOIN и объясните риск.
3. Разделите числовое равенство и представление числа: `1.250` и `1.25` равны по значению, но могут иметь разный scale.
4. Не делайте итоговую массу модуля суммой всех измерений: здесь несколько записей могут описывать один объект.

```text
docker compose run --rm java practice/java/advanced/QuantityService.java
```

## Сценарии и самостоятельная оценка

| Строка | Ожидаемый статус | Масса, kg |
| --- | --- | --- |
| M1, 1250 g | KNOWN | 1.25 |
| M2, 1.250 kg | KNOWN | 1.25 |
| M3, NULL kg | UNKNOWN | отсутствует |
| M4, NaN kg | INVALID | отсутствует |
| M5, -1 kg | INVALID | отсутствует |
| M6, 3 m | DIMENSION_MISMATCH | отсутствует |
| M7, 0 kg | INVALID | отсутствует |

Вы должны получить семь строк, без потерь и без исключения на M4. Исходные значения не исправляются в БД. Объясните, почему UNKNOWN и INVALID требуют разных действий оператора. Проверьте отдельно `0.001`, `1e3`, ` 1`, `1,5`, `+1`, а также границу длины; не меняйте грамматику молча ради одного примера.

## Дополнительное исследование

Расширьте модель состоянием NOT_APPLICABLE с обязательным основанием. Затем отдельно добавьте перевод kg → g с указанной точностью вывода; округляйте только при представлении. В третьем варианте храните исходную единицу, версию правила и происхождение результата. Эти расширения требуют собственного кода и не входят в эталонный метод.
