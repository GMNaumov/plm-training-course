# L03. План запроса и восстановление копии

[Каталог заданий](../README.md) · [Глоссарий](../../../references/glossary.md)

## Постановка задачи

Эксплуатация должна обосновать индекс и показать пригодность резервной копии. Исследуйте синтетическую нагрузку и восстановите учебные данные в отдельную БД.

1. Заготовка создаёт TEMP-таблицу perf из 100000 строк с 1000 значениями parent_id. Выполните ANALYZE и EXPLAIN (ANALYZE, BUFFERS) для DM-100. Сохраните число найденных строк, тип сканирования и отличие оценки от факта.
2. Добавьте B-tree индекс по parent_id, повторите ANALYZE и план в той же сессии. Объясните стоимость обслуживания индекса и почему малый объём или другой предикат могут сделать последовательное чтение разумным.
3. Выполните команды backup и restore из блока ниже. Копия восстанавливается в plm_restore, а не поверх plm. Через явные lab.item, lab.revision и lab.base_tree сравните количество и содержимое идентификаторов с исходной БД.
4. Назовите, какие внешние файлы, роли и настройки не подтверждаются таким pg_dump. Учебные URI документов не содержат настоящих файлов, поэтому их наличие в таблице не является восстановлением документного хранилища.

## Предварительные условия

Прочитайте [теорию темы 04](../../../course/04-operations-and-performance/theory.md) и связанные подтемы ниже. Уровень: уверенный SQL. Поднимите [контейнерную среду](../../environment/README.md).

Перед началом выполните `reset`: это возвращает общую исходную базу ДМ-01 и удаляет результаты предыдущего задания в схеме lab. Все практикумы независимы по данным; проходите их в порядке номеров для последовательного освоения. Не выполняйте reset посреди практикума. Файлы в practice/output reset не удаляет.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File practice/environment/lab.ps1 reset
```

Команды в заданиях выполняются из корня репозитория. Для Ubuntu: `bash practice/environment/lab.sh reset`. Редактируйте заготовку на хосте любым редактором; SQL и код исполняйте в контейнерах.

## Заготовки и запуск

[SQL-заготовка L03](../../postgresql/queries/l03.sql). Выполните после заполнения:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File practice/environment/lab.ps1 sql practice/postgresql/queries/l03.sql
```

В Ubuntu: `bash practice/environment/lab.sh sql practice/postgresql/queries/l03.sql`. Для интерактивных опытов используйте действие `psql`; после ожидаемого SQL-отказа внутри транзакции выполните ROLLBACK. Скрипт sql останавливается на неожиданной ошибке.

Отдельно выполните из корня:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File practice/environment/lab.ps1 backup
powershell -NoProfile -ExecutionPolicy Bypass -File practice/environment/lab.ps1 restore
docker compose exec db psql -X -U plm_owner -d plm_restore -c "SELECT count(*) FROM lab.base_tree;"
```

В Ubuntu эквивалент: `bash practice/environment/lab.sh backup`, затем `restore`; последняя команда docker одинакова. Для сверки ключей в обеих БД выполните `SELECT id FROM lab.item ORDER BY id;` и аналогичный запрос revision. Для сравнения значимых связей получите `SELECT path,revision_id,quantity,unit FROM lab.base_tree ORDER BY path;` в обеих БД.

## Критерии самостоятельной оценки

Предикат возвращает 100 строк до и после индекса. Планы и времена записаны с указанием среды; конкретное ускорение не требуется. В plm_restore имеются 9 изделий, 13 ревизий и 9 путей BASE-01; идентификаторы совпадают с исходником. Зафиксировано, что TEMP perf не входит в резервную копию, а восстановление SQL не подтверждает восстановление внешних файлов.

Сохраните собственный SQL/код, результаты и краткое объяснение оснований решения. Сравнивайте предметный смысл, точные ключи, количества и отказы; порядок строк без ORDER BY и времена выполнения могут отличаться. Автоматического оценивания, баллов и обязательной сдачи нет.
