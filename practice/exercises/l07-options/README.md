# L07. Ограничения опций на Python

[Каталог заданий](../README.md) · [Глоссарий](../../../references/glossary.md)

## Постановка задачи

Реализуйте логическую проверку вариантов модуля. Исходный файл options.json содержит пять конфигураций, в том числе неполную. Готовую функцию запускать пока нельзя: заготовка намеренно бросает NotImplementedError.

1. Изучите обвязку practice/python/options.py. Реализуйте validate(config), возвращающую статус и список причин. Допустимые значения: redundant — bool, controller — SINGLE/DUAL, firmware — FW-A/FW-B. Пропущенный ключ и None означают неполноту.
2. Ограничения: redundant=true требует DUAL; DUAL требует FW-B. Проверка известных нарушений имеет приоритет над INCOMPLETE. Не превращайте None в False и не принимайте произвольную строку за bool.
3. Запустите программу в контейнере, затем вручную исследуйте комбинации с отсутствующим полем, неверным типом и частичным противоречием. Сохраняйте все причины, а не только первую.
4. Для полного допустимого выбора покажите, включается ли o35 и сколько датчиков получилось. Сверьтесь с SQL-заготовкой.
5. Объясните, почему C3 при логическом VALID всё ещё не готова к изготовлению: FW-B пока draft, а выпущенное определение аппаратного DUAL в данных не создано. Не создавайте его автоматически и не считайте логическую проверку подтверждением совместимости.

## Критерии самостоятельной оценки

Статусы C1…C5: VALID, INVALID, VALID, INCOMPLETE, INVALID. C2 нарушает REDUNDANT→DUAL, C5 — DUAL→FW-B. Базовое исполнение имеет один датчик, резервированное — два. Неизвестные значения не проходят как допустимые. Отдельно описаны логическая допустимость, наличие конструкции, разрешённая ревизия и подтверждённая совместимость.

Сохраните собственный SQL/код, результаты и краткое объяснение оснований решения. Сравнивайте предметный смысл, точные ключи, количества и отказы; порядок строк без ORDER BY и времена выполнения могут отличаться. Автоматического оценивания, баллов и обязательной сдачи нет.
