# L04. Единицы, неизвестные значения и свойства

[Каталог заданий](../README.md) · [Глоссарий](../../../references/glossary.md)

## Постановка задачи

В каталог перенесены массы корпуса, ротора, датчика и жгута. Числа записаны в разных единицах, одно значение отсутствует, а одна единица относится к длине. Получите корректный отчёт без правдоподобных подстановок.

1. Загрузите measurements.csv во временную таблицу через готовую команду. Соедините её со справочником unit внешним соединением, чтобы неизвестная единица не потеряла строку.
2. Нормализуйте массу в kg через factor. Выведите исходную единицу, нормализованное значение и диагноз OK, UNKNOWN, UNKNOWN_UNIT или DIMENSION_MISMATCH. Отсутствующая масса не равна нулю, а длина 100 mm не становится массой 0.1 kg.
3. Создайте таблицу mass_property с FK на ревизию и единицу, положительным известным значением и явными статусами known/unknown/not_applicable. Сохраните только разобранные факты; ошибку жгута оставьте в отчёте для владельца НСИ.
4. Укажите, какое дополнительное ограничение требуется для размерности свойства. Выберите вариант: ограниченная таблица допустимых единиц с FK, сервисная проверка либо триггер. Обоснуйте место правила и последствия добавления новой единицы.

## Критерии самостоятельной оценки

HO-A: OK и 2.5 kg; RO-A: OK и 1.2 kg; SEN-A: UNKNOWN и NULL; HAR-A: DIMENSION_MISMATCH и NULL. В таблице свойств нет ложного нуля и ложной массы жгута. Проверки статуса не допускают known с NULL и unknown с числом. Объяснено, что FK на unit подтверждает существование единицы, но не её допустимость для массы.

Сохраните собственный SQL/код, результаты и краткое объяснение оснований решения. Сравнивайте предметный смысл, точные ключи, количества и отказы; порядок строк без ORDER BY и времена выполнения могут отличаться. Автоматического оценивания, баллов и обязательной сдачи нет.
