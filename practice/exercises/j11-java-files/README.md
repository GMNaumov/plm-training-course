# J11. Параллельный манифест файлов и происхождение результата

[Все задания](../README.md) · [Java-ветка](../../java/advanced/README.md) · [Теория документов](../../../course/07-documents-and-files/theory.md) · [Глоссарий](../../../references/glossary.md)

## Задача и предварительные условия

Прочитайте тему 07 и границы интеграции CAD/CAM/CAE темы 16. Нужны потоки ввода, SHA-256, Future, Semaphore и JDBC. Создайте сервис проверки байтов файлов с ограниченным параллелизмом и сохранением предметной роли каждого файла.

После reset три строки `java_file_manifest` ссылаются на синтетические тексты в [java-files](../../datasets/java-files/housing.txt). housing.txt и housing-copy.txt имеют одинаковые байты, но разные роли и версии условного инструмента. В файлах нет геометрии, реальных управляющих программ и результатов расчёта.

## Контракт и реализация

В [FileProvenance.java](../../java/advanced/FileProvenance.java) реализуйте `hash` и `calculate`:

1. Прочитайте неизменяемый список Job в согласованном снимке БД; максимум 1000 записей. Закройте читающую транзакцию до длительного файлового I/O.
2. Разрешайте относительный путь от `/workspace/practice/datasets/java-files`; используйте toRealPath и проверьте принадлежность реальному корню и обычный файл. В Compose источники read-only, их конкурентная подмена не входит в контракт.
3. Вычисляйте SHA-256 потоково, не читая весь файл в память. Хеш относится к байтам; role и tool_version относятся к происхождению и смыслу.
4. Используйте виртуальные потоки JDK и Semaphore(4), взятый **до submit**. Не создавайте тысячу ожидающих файловых операций. Потокобезопасность JDBC не предполагается: работники не получают Connection.
5. При отказе отмените оставшиеся задачи и не сохраняйте частичный run. После полного вычисления сохраните все результаты одной короткой транзакцией. Порядок отчёта соответствует стабильному порядку манифеста, а не случайному порядку завершения.

```text
docker compose run --rm java practice/java/advanced/FileProvenance.java FILES-1
```

## Сценарии и самостоятельная оценка

Ожидаются три строки в java_file_digest. У двух housing-файлов SHA-256 совпадает, но в БД остаются обе записи с разными role/tool_version. Controller имеет другой хеш. Совпадение хеша не разрешает склеить исходник и представление в один объект.

После отдельного reset добавьте недостающую зависимость:

```text
docker compose exec -T db psql -X -U plm_owner -d plm -v ON_ERROR_STOP=1 -f /workspace/practice/java/advanced/j11-missing.sql
docker compose run --rm java practice/java/advanced/FileProvenance.java FILES-FAIL
```

Процесс отказывает, строк FILES-FAIL нет. Отдельно добавьте путь `../seed.sql`: даже существующий файл вне разрешённого корня должен быть отвергнут. Повтор FILES-1 после уже успешного сохранения приводит к конфликту ключа, не к замене происхождения; это явный контракт без идемпотентного runId.

Наблюдайте отмену без ожидания конкретного порядка сообщений. Interrupt не обещает мгновенное прекращение любого файлового I/O; опубликованный набор мал, а время длинных внешних операций потребует отдельной политики deadline. Список задач ограничен 1000, одновременное выполнение — четырьмя разрешениями; наличие виртуальных потоков само по себе не ограничивает нагрузку.

## Углубление

Добавьте версию манифеста и подтверждение применённого набора зависимостей. Затем спроектируйте двухфазную фиксацию содержимого и метаданных с уборкой неподтверждённых файлов; затем идемпотентный runId с проверкой точного договора. Хеширование и метаданные не доказывают пригодность модели для расчёта, актуальность реальной CAD-ассоциации или инженерное качество представления.
