# J04. Предметная разность двух снимков BOM

[Все задания](../README.md) · [Java-ветка](../../java/advanced/README.md) · [Теория изменений](../../../course/12-change-and-workflow/theory.md) · [Глоссарий](../../../references/glossary.md)

## Задача и предварительные условия

Прочитайте L05, L09 и контракт J03. Нужны Map, множества, record и BigDecimal. Сервис должен сравнить два принятых снимка по вхождениям, сохранив смысл различий. Совпадение общего количества крепежа не означает совпадения конструкции.

Выполните reset. Готовые OLD и NEW независимы от выполнения J03. NEW — синтетический набор для анализа дельты, а не заявление о выпущенной и совместимой конструкции. В нём изменены два пути: датчик и крепёж блока управления.

## Реализация и запуск

В [BomDiff.java](../../java/advanced/BomDiff.java) заполните `load` и `compare`:

1. Убедитесь, что заголовок существует и запечатан. Неверный id не должен дать «нулевую разность» с пустым набором.
2. Прочитайте оба снимка в одной REPEATABLE READ; индексируйте строки по полному пути.
3. Постройте объединение путей. Отсутствие с одной стороны означает ADDED либо REMOVED, а не нулевое количество.
4. Для общего пути сравните идентичность родителя и child_item, ревизию, единицу, локальное и корневое количества. Возвращайте все обнаруженные категории; не останавливайтесь на первой.
5. Для чисел используйте compareTo. Смена единицы требует UNIT_REVIEW; сервис не пересчитывает единицы и не утверждает эквивалентность нормы.

```text
docker compose run --rm java practice/java/advanced/BomDiff.java OLD NEW
docker compose run --rm java practice/java/advanced/BomDiff.java OLD OLD
```

## Ожидаемый результат и самостоятельная оценка

OLD → NEW: `o30 REVISION` и `o50/e20 LOCAL_QUANTITY,ROOT_QUANTITY`, всего два изменённых пути. OLD → OLD: ноль. NEW → OLD сохраняет те же категории, хотя направление значений обратное. Снимок ABSENT должен вызвать MISSING_ROW, а не пустой отчёт.

Проверьте, что OLD содержит 12 ea крепежа, NEW — 13. Эти агрегаты полезны для сверки, но не заменяют пути. Изменение 6→7 в одной ветви и 4→3 в другой оставило бы итог прежним при двух изменённых вхождениях.

## Более глубокие варианты

После своей реализации подготовьте новые снимки с удалённым путём и новым путём; существующие запечатанные OLD/NEW не меняйте. Перенос узла между родителями базовый алгоритм покажет как REMOVED+ADDED. Предложите отдельное правило сопоставления вхождений и докажите, когда оно неоднозначно: совпадение child_item недостаточно.

Затем спроектируйте трёхстороннее согласование: исходная EBOM, новая EBOM и текущая MBOM с принятыми технологическими отличиями. Объясните, почему прямое копирование новой EBOM потеряет обоснованные производственные решения. Эталон J04 реализует двустороннюю диагностику, без автоматического merge и принятия изменений.
