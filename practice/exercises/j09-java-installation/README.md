# J09. Конкурентная установка физического компонента

[Все задания](../README.md) · [Java-ветка](../../java/advanced/README.md) · [Теория](../../../course/15-physical-product-lifecycle/theory.md) · [Глоссарий](../../../references/glossary.md)

## Задача и предварительные условия

Прочитайте L12. Нужны OffsetDateTime, диапазоны PostgreSQL, транзакции и блокировки строк. Сервис установки должен одновременно защищать два инварианта: одну позицию нельзя занять двумя компонентами и один компонент нельзя установить в двух местах в пересекающееся время.

Выполните reset и `j09-serials.sql` командой psql с `-f /workspace/practice/java/advanced/j09-serials.sql`. Появятся DM-101, S-003 и S-004. История DM-100 не меняется до вашего действия. Сервис работает в общей installation; перед другими заданиями снова reset.

## Граница модели

Контракт одноуровневый: родитель — assembly, ребёнок — part. Эта типовая граница исключает циклы установок; вложенная иерархия сборок потребует другого протокола анализа предков. Проверки применяемости ревизий, аппаратуры/ПО, решения о допустимой замене и полномочий пользователя сюда не включены. Успешная установка означает согласованную запись двух инвариантов, не инженерное разрешение.

Интервалы полуоткрыты `[from,to)`, `-` вместо to означает бесконечную верхнюю границу. from/to передаются с часовым смещением. recorded_at — часы БД при записи; это не полноценная двухвременная история исправлений.

## Реализация и запуск

В [InstallationService.java](../../java/advanced/InstallationService.java) заполните `install`:

1. Проверьте параметры и границы интервала.
2. Заблокируйте обе serial_unit в стабильном порядке id. Не ограничивайтесь родителем: конкурентная установка того же ребёнка в другой родитель иначе пройдёт.
3. Подтвердите существование и типы объектов. В READ COMMITTED после ожидания блокировки отдельным statement прочитайте актуальную историю.
4. Отвергните любое пересечение по `(parent_serial, position)` **или** по `child_serial`. Используйте `tstzrange` и оператор `&&`; NULL верхней границы не сравнивайте обычным `<`.
5. Вставьте запись с причиной и recorded_at одной транзакцией. Все писатели установки обязаны соблюдать тот же протокол; схема исходного L12 сама его не обеспечивает.

```text
docker compose run --rm java practice/java/advanced/InstallationService.java JI-1 DM-101 30 S-003 2026-09-01T00:00:00Z - training
docker compose run --rm java practice/java/advanced/InstallationService.java JI-2 DM-101 30 S-004 2026-09-01T00:00:00Z - training
docker compose run --rm java practice/java/advanced/InstallationService.java JI-3 DM-100 40 S-003 2026-09-01T00:00:00Z - training
```

Первый вызов INSTALLED, второй — пересечение позиции, третий — пересечение занятости ребёнка. Последний аргумент training — явная метка учебного CLI, не полномочие.

## Границы и конкурентность

После нового reset и fixture установите S-001 в DM-101 с `2026-08-10T00:00:00Z`. Это точная граница завершения прежней установки S-001 в DM-100, поэтому пересечения нет. Начало на секунду раньше должно отказать. Прежняя I-1 сохраняется как история.

После отдельного reset запускайте попарно в двух терминалах: два ребёнка в DM-101/30; один ребёнок в DM-100/40 и DM-101/30. В каждой паре ровно одна успешная запись, другая — OVERLAPPING_INSTALLATION. Наблюдайте БД; какой клиент победит, не задано.

## Самооценка и углубление

Объясните область блокировки для обоих конфликтов и почему сортировка снижает риск deadlock. Предложите exclusion constraints как защиту от писателей вне сервиса с оценкой необходимых операторных классов; затем отдельный атомарный replace с закрытием прежней установки; затем расширение на вложенные сборки. Эти механизмы не входят в эталон и не должны имитироваться удалением истории.
