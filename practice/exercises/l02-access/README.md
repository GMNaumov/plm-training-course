# L02. Доступ и неполный результат

[Каталог заданий](../README.md) · [Глоссарий](../../../references/glossary.md)

## Постановка задачи

Администратор готовит представление каталога для читателя. Читатель видит идентичности изделий и только выпущенные ревизии; состав и изменение данных ему недоступны. Реализуйте это в собственной учебной БД.

1. Выдайте NOLOGIN-роли lab_reader минимальные права на схему и две таблицы item/revision. Не выдавайте права на все таблицы или будущие объекты.
2. Включите Row-Level Security (RLS, защиту строк) на revision. Политика SELECT для lab_reader допускает state=released. Выполните SET ROLE и прочитайте список.
3. В интерактивной сессии под lab_reader отдельно попробуйте UPDATE revision и SELECT occurrence. Запишите ожидаемые отказы, затем RESET ROLE. Отказ не должен прерывать общий файл успешных действий.
4. Сравните видимые ревизии с владельцем БД. Сформулируйте ответ сервиса, которому нужны невидимые определения: нельзя объявлять скрытую зависимость отсутствующей конструкцией.
5. Объясните, почему SET ROLE не проверяет пароль, а запрос суперпользователя не проверяет действие RLS для обычного читателя.

## Предварительные условия

Прочитайте [теорию темы 03](../../../course/03-administration-and-security/theory.md) и связанные подтемы ниже. Уровень: уверенный SQL. Поднимите [контейнерную среду](../../environment/README.md).

Перед началом выполните `reset`: это возвращает общую исходную базу ДМ-01 и удаляет результаты предыдущего задания в схеме lab. Все практикумы независимы по данным; проходите их в порядке номеров для последовательного освоения. Не выполняйте reset посреди практикума. Файлы в practice/output reset не удаляет.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File practice/environment/lab.ps1 reset
```

Команды в заданиях выполняются из корня репозитория. Для Ubuntu: `bash practice/environment/lab.sh reset`. Редактируйте заготовку на хосте любым редактором; SQL и код исполняйте в контейнерах.

## Критерии самостоятельной оценки

Под lab_reader видны 11 выпущенных ревизий; HO-C и FW-B скрыты. UPDATE и чтение occurrence отклонены. Владелец видит 13 ревизий. Роль не получила DDL и записи. В выводе отражено, что разрешённый список не доказывает полноту инженерной конфигурации.

Сохраните собственный SQL/код, результаты и краткое объяснение оснований решения. Сравнивайте предметный смысл, точные ключи, количества и отказы; порядок строк без ORDER BY и времена выполнения могут отличаться. Автоматического оценивания, баллов и обязательной сдачи нет.
