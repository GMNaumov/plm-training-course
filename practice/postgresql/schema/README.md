Ключи текстовые и короткие ради чтения, не промышленная система нумерации. FK occurrence(child_item,fixed_revision) не позволяет зафиксировать ревизию чужого изделия. Допускается NULL fixed_revision для плавающей ссылки, но учебный BASE-01 содержит точный выбор. Наличие FK не гарантирует отсутствие циклов, допустимость ревизий, полноту свидетельств, размерность свойств, отсутствие пересечений установок или готовность производства. Эти границы исследуются в заданиях.

BASE-01 и base_tree — исходный снимок для базового исполнения. Представление готово для независимости L10 от реализации L05; не читайте его определение до собственной попытки L05. Внешние файлы и реальные инженерные документы не поставляются; URI обозначают только условный объект.

Новые таблицы iteration и mass_property обучающийся создаёт в L01/L04. Схема хранит намеренно слабые места (например, источник документа не обязан совпадать с целью evidence), чтобы показать различие ссылочной и предметной целостности. Их нельзя считать проектом промышленной схемы.

## Уточнения после статической ревизии

BASE-01 фиксирует выбор ревизий для подготовленного исходного состава. Поля количества и родителя остаются в изменяемой occurrence; самостоятельной неизменяемой версии структуры нет. FK baseline.revision_id подтверждает существование ревизии, но не её принадлежность child_item выбранного вхождения. INNER JOIN с baseline не различает отсутствующую обязательную запись и сознательно исключённую опциональную ветвь. Эти ограничения не меняют ожидаемые результаты исходного набора, но ограничивают обобщение алгоритма.

В нескольких таблицах проверка numeric > 0 не исключает NaN и положительную бесконечность. Для migration_stage/target конечность уже проверяется отдельно. Общий домен конечных инженерных величин пока не введён. requirement/evidence, resource.qualified и allocation также являются сокращёнными моделями: они не обеспечивают полную историю требований, квалификации и материальных потоков.

[Предложения P01–P05](../../../docs/practice-expansion-proposals.md) описывают способы развития. В текущей ревизии исполняемая схема и данные сохранены. Это выводы чтения кода, а не новый протокол контейнерных испытаний.
