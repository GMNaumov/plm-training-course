# Глоссарий PLM/PDM

[К разделу](README.md)

Определения ниже задают смысл терминов в курсе. У поставщиков и предприятий границы понятий и названия объектов могут отличаться. В частности, «версия», «ревизия», «замена», «отклонение» и «набор данных» требуют проверки контекста. Английский термин приводится для поиска в документации, а не как обещание полного совпадения механизмов.

## Управление изделием и системный ландшафт

| Термин | Расшифровка и значение |
| --- | --- |
| PLM | Product Lifecycle Management — управление жизненным циклом изделия: определением, изменениями, решениями и связанными данными от замысла до завершения эксплуатации. |
| PDM | Product Data Management — управление данными об изделии, включая структуры, документы, файлы, версии и связи. |
| Жизненный цикл | Этапы существования изделия и управления его определением. Жизнь физического объекта и состояния его документации различаются. |
| Цифровая нить, digital thread | Прослеживаемые связи решений, определений, фактов и подтверждений по жизненному циклу. |
| Прослеживаемость, traceability | Возможность установить происхождение, связи и историю объекта или решения в заданной области. |
| CAD | Computer-Aided Design — компьютерное проектирование, включая создание геометрических моделей и чертежей. |
| CAM | Computer-Aided Manufacturing — компьютерная подготовка изготовления, в том числе обработки и управляющих данных. |
| CAE | Computer-Aided Engineering — компьютерный инженерный анализ и расчётное обоснование. |
| ERP | Enterprise Resource Planning — планирование ресурсов предприятия и связанные хозяйственные процессы. |
| MES | Manufacturing Execution System — система поддержки управления исполнением производства и регистрации производственных фактов. |
| Система-владелец | Назначенный источник управления конкретным объектом или атрибутом; не обязательно одна система для всех сведений об изделии. |
| Единый источник достоверных данных | Управляемое владение сведениями и согласованные правила их использования; не обязательно физическое хранение в одной базе. |
| Заинтересованная сторона, stakeholder | Участник, чьи потребности, ограничения или ответственность значимы для решения. |

Подробности: [основы](../course/01-plm-pdm-foundations/theory.md), [ландшафт интеграций](../course/17-apis-and-enterprise-integration/theory.md).

## Объекты, версии и хранение данных

| Термин | Расшифровка и значение |
| --- | --- |
| Изделие, item/part | Управляемое определение компонента или сборки с устойчивой идентичностью; не обязательно физический экземпляр. Английские названия зависят от системы. |
| Идентичность | Основание считать объект тем же самым независимо от изменения имени и других свойств. |
| Обозначение | Бизнес-идентификатор в установленной области уникальности; отличается от внутреннего ключа хранения. |
| Тип объекта | Определение допустимых свойств, связей и поведения группы объектов. |
| Атрибут | Свойство с определённым смыслом, типом значения и правилами заполнения. |
| Метаданные | Структурированные сведения об объекте или содержимом: идентификаторы, свойства, состояния, связи и происхождение. |
| Кратность | Допустимое число значений свойства или участников отношения. |
| Семантика | Предметный смысл данных, отношений и операций; отличается от их внешнего формата и написания. |
| Алиас | Дополнительное или прежнее имя объекта с определённой областью использования; не обязательно самостоятельная идентичность. |
| Нормализация данных | Приведение представления и структуры к установленным правилам при сохранении смысла. В реляционном моделировании также означает устранение определённых зависимостей и избыточности. |
| Версия, version | Общее обозначение состояния данных во времени; без уточнения может означать разные уровни версионирования. |
| Ревизия, revision | В соглашении курса — контролируемый пересмотр определения изделия или документа. |
| Итерация, iteration | В соглашении курса — рабочее сохранение внутри одной ревизии. |
| Состояние, lifecycle state | Степень зрелости управляемого объекта и связанные разрешённые действия. |
| Выпуск, release | Управляемое разрешение использования определения после выполнения установленных условий. |
| Реляционная модель | Представление данных через отношения, обычно реализованные таблицами с ключами и ограничениями. |
| Первичный ключ | Уникальный идентификатор записи в выбранной таблице; не обязательно инженерное обозначение. |
| Внешний ключ | Ограничение, связывающее значение со существующей записью другой или той же таблицы. |
| Ссылочная целостность | Отсутствие недопустимых ссылок на несуществующие объекты. Не доказывает инженерную корректность связей. |
| Инвариант | Условие, которое должно сохраняться в каждом допустимом состоянии модели. |
| Транзакция | Локальная единица согласованного изменения данных с установленными свойствами фиксации и отмены. |
| Атомарность | Свойство операции применяться в установленной границе целиком либо не оставлять частично принятого результата. Для нескольких систем не возникает автоматически. |
| Изоляция транзакций | Правила видимости и взаимодействия параллельных транзакций. |
| Оптимистический контроль | Проверка того, что исходная версия не изменилась перед фиксацией результата; конфликт требует разрешения. |
| Лексикографический порядок | Порядок сравнения строк по последовательности символов. Может отличаться от инженерного порядка ревизий или серийных номеров. |
| Пессимистический контроль | Ограничение конкурентных действий блокировками по выбранной политике. |
| Взаимная блокировка, deadlock | Циклическое ожидание ресурсов, при котором участники не могут продолжить без разрешения ситуации. |
| Сериализация операций | Обеспечение эффекта, согласованного с некоторым последовательным выполнением конфликтующих действий. |
| БД / СУБД | База данных / система управления базами данных. PostgreSQL — используемая в проекте предполагаемая СУБД. |
| SQL | Structured Query Language — язык определения, выборки и изменения реляционных данных. |
| CTE | Common Table Expression — общее табличное выражение, именованный промежуточный результат запроса; рекурсивный CTE поддерживает обход иерархий и графов. |
| JSON | JavaScript Object Notation — текстовый формат структурированных данных. Гибкость формата не отменяет предметных ограничений. |

Подробности: [предметная модель](../course/02-domain-and-data-model/theory.md).

## Состав, конфигурация и вариантность

| Термин | Расшифровка и значение |
| --- | --- |
| BOM | Bill of Materials — структурированное представление состава изделия с компонентами и атрибутами их участия. |
| EBOM | Engineering Bill of Materials — инженерное представление состава, отражающее проектное устройство изделия. |
| MBOM | Manufacturing Bill of Materials — производственное представление состава для принятого способа изготовления и контекста площадки. |
| Вхождение, occurrence | Участие компонента в конкретном месте родительской структуры. Имеет идентичность и атрибуты отношения. |
| Позиция состава | Место или строка участия компонента в используемом представлении. Позиционный номер не является глобальным идентификатором изделия. |
| Количество | Мера участия компонента во вхождении; интерпретируется вместе с единицей и базой расчёта. |
| Граф | Модель вершин и рёбер. BOM допускает повторное использование компонентов в разных ветвях. |
| Путь | Последовательность связанных вершин или вхождений от исходного объекта до результата. |
| Цикл состава | Возврат к предку по отношениям включения; нарушает обычную семантику конечного раскрытия BOM. |
| Раскрытие, explosion | Последовательный обход дочерних компонентов выбранного состава. |
| Where-used | Обратный поиск объектов и вхождений, в которых используется компонент. |
| Агрегирование, roll-up | Вычисление итогов по раскрытой структуре с учётом повторных путей и правил количества. |
| Альтернатива | Заранее предусмотренный вариант выбора по установленной политике; точный механизм зависит от контекста. |
| Замена, substitute | Разрешённое использование одного объекта вместо другого в заданных условиях. Не обязательно взаимное. |
| Взаимозаменяемость | Пригодность взаимной замены в определённом контексте; не выводится только из похожести признаков. |
| Транзитивность отношения | Свойство, при котором из отношения A к B и B к C следует такое же отношение A к C. Для контекстных разрешений замены не предполагается автоматически. |
| Конфигурация | Конкретное сочетание управляемых определений и условий их выбора. |
| Разрешение конфигурации, resolution | Вычисление конкретных участвующих объектов и версий по структуре, правилам и контексту. |
| Ревизионное правило | Условие выбора ревизии по ссылке с учётом допуска и приоритетов. |
| Зафиксированная ссылка | Ссылка на конкретное управляемое определение или версию. |
| Плавающая ссылка | Ссылка, конкретная версия по которой выбирается при разрешении. |
| Применяемость, effectivity | Область действия определения или связи, например по дате, серии или партии. |
| Полуоткрытый интервал | Интервал с включённой одной и исключённой другой границей; в примерах дат курса включается начало и исключается конец. |
| Базовая линия, baseline | Контролируемо принятый набор определений с известной границей полноты и порядком изменений. |
| Замыкание зависимостей | Включение связанных определений до установленной границы, необходимой для воспроизведения выбранного набора. |
| Снимок, snapshot | Зафиксированное состояние данных. Сам факт снимка не означает утверждения как базовой линии. |
| Семейство изделий | Группа исполнений, объединённых общими решениями и управляемыми различиями. |
| Признак, feature | Вопрос или параметр вариантной модели, имеющий допустимые значения. |
| Опция, option | Управляемый вариант выбора; конкретное соотношение терминов «признак» и «опция» зависит от модели. |
| Пакет опций | Именованное объединение нескольких согласованных выборов; правила раскрытия в признаки и дальнейшего изменения задаются моделью семейства. |
| Домен | Множество допустимых значений признака или атрибута. |
| Ограничение вариантов, constraint | Правило допустимости сочетаний значений, включая зависимости, исключения и числовые условия. |
| Кардинальность выбора | Ограничение количества выбранных значений, например «ровно одно» или «не более двух». |
| 150-процентный состав | Условное название вариантной структуры, объединяющей альтернативные и условные элементы семейства. |
| 100-процентный состав | Представление выбранного исполнения; дополнительно требует согласованного разрешения ревизий и применяемости. |
| Интерфейс изделия | Граница взаимодействия компонентов: геометрия, электрические соединения, протоколы и другие согласованные свойства. |
| Reconciliation | Согласование связанных представлений, выявление и объяснение расхождений и изменений. |

Подробности: [EBOM](../course/08-engineering-bom/theory.md), [ревизионная конфигурация](../course/09-revision-configuration/theory.md), [варианты](../course/10-option-configuration/theory.md), [MBOM](../course/13-manufacturing-bom/theory.md).

## НСИ, классификация и документы

| Термин | Расшифровка и значение |
| --- | --- |
| НСИ | Нормативно-справочная информация — управляемые общие значения и определения, используемые при ведении предметных данных. |
| Мастер-данные, master data | Общие устойчивые определения ключевых сущностей предприятия, используемые несколькими процессами и системами. |
| Транзакционный факт | Запись о совершившемся событии или операции, например поставке партии; отличается от общего определения материала. |
| Справочник | Набор управляемых значений с идентификаторами и правилами использования. |
| Размерность | Физический смысл величины, например масса или длина; определяет допустимые операции и преобразования единиц. |
| Допуск | Разрешённая область отклонения характеристики; отличается от точности её числового представления. |
| Спецификация материала | Управляемое описание требований к материалу и его состоянию; не равно отдельной поставленной партии. |
| Классификация | Отнесение объектов к классам по установленным признакам для описания, поиска и выбора. |
| Таксономия | Система классов и отношений между ними по принятому основанию группировки. |
| Параметрический поиск | Отбор по формализованным характеристикам, диапазонам и условиям. |
| Ранжирование | Упорядочение прошедших обязательный отбор кандидатов по предпочтениям. Не заменяет проверку допуска. |
| Проверка корректности данных, data validation | Оценка типов, структуры и предметных ограничений значений. Отличается от инженерной валидации пригодности системы для предполагаемого использования. |
| Аналог | Кандидат со схожими свойствами; статус аналога не означает автоматического разрешения замены. |
| Документ | Управляемый объект с назначением, историей, состоянием и содержимым. |
| Файл | Двоичное или текстовое содержимое, связанное с управляемым объектом. |
| Набор данных, dataset | В курсе — логическая группировка связанных ресурсов. Конкретная сущность с таким именем зависит от продукта. |
| Check-out | Резервирование редактирования и получение содержимого по политике системы. |
| Check-in | Возврат содержимого и фиксация управляемого результата сохранения. |
| Представление, rendition | Производная форма содержимого для просмотра или передачи с известным исходником. |
| Публикация | Управляемая подготовка и выдача определённого набора материалов адресату. |
| Контрольная сумма | Значение, вычисленное по содержимому для проверки совпадения или целостности байтов. Не равна разрешению применения или подписи. |
| PDF | Portable Document Format — формат представления документов; формат сам по себе не подтверждает утверждения содержания. |

Подробности: [НСИ](../course/05-master-and-reference-data/theory.md), [классификация](../course/06-product-classification/theory.md), [документы](../course/07-documents-and-files/theory.md).

## Требования, изменения и согласование

| Термин | Расшифровка и значение |
| --- | --- |
| Требование | Необходимое свойство или ограничение с определёнными условиями и возможностью подтверждения. |
| Декомпозиция | Разделение определения или требования на связанные части; корректность покрытия требует отдельного обоснования. |
| Распределение требований, allocation | Назначение требований элементам реализации и ответственности. Не означает доказанного выполнения. |
| Свидетельство, evidence | Данные или материалы, на которых основывается заключение, с известными происхождением и областью действия. |
| Покрытие | Соответствие между областью требований или объектов и реализацией, распределением либо подтверждениями. Значение определяется ролью связи и контекстом, а не одним количеством ссылок. |
| Бюджет характеристики | Принятое распределение общего ограничения или допустимого вклада между подсистемами с определённым способом объединения. |
| Подозрительная связь, suspect link | Отношение, актуальность которого требует оценки после изменения участника; пометка не означает автоматической инженерной непригодности. |
| Верификация, verification | Подтверждение соответствия установленным требованиям. |
| Валидация, validation | Подтверждение пригодности для предполагаемого использования и потребностей заинтересованных сторон. |
| Матрица покрытия | Сопоставление требований с реализацией, методами и свидетельствами; наличие ссылок не доказывает достаточность подтверждения. |
| Сертификационный контекст | Выбранная область требований и процедур оценки соответствия. В курсе конкретная нормативная база не назначена. |
| Workflow | Поток выполнения задач и решений, например процесса согласования. Отличается от маршрута изготовления. |
| ECR | Engineering Change Request — запрос на инженерное изменение. Роль и жизненный цикл определяются предприятием. |
| ECO | Engineering Change Order — распоряжение или управляемый документ выполнения инженерного изменения по принятой политике. |
| ECN | Engineering Change Notice — извещение об инженерном изменении. Порядок ECR/ECO/ECN не универсален. |
| Анализ влияния, impact analysis | Поиск и оценка последствий изменения для связанных определений, процессов и физических изделий. |
| Целевая популяция | Определённое множество экземпляров или объектов, рассматриваемых анализом либо назначенным действием, с сохраняемыми критериями включения. |
| Внедрение изменения | Реализация принятого решения в необходимых областях, включая передачу, производство и нужные экземпляры. |
| Несоответствие, nonconformance | Зафиксированное отличие фактического состояния от установленного требования. |
| Отклонение / временное разрешение | Ограниченное решение о допустимом отличии по установленной процедуре. Термины deviation и waiver требуют организационного и нормативного контекста. |
| Компенсация | Предметно осмысленное действие по устранению последствий ранее выполненной операции; не всегда техническая отмена. |

Подробности: [требования](../course/11-requirements-management/theory.md), [изменения](../course/12-change-and-workflow/theory.md).

## Производство и физическое изделие

| Термин | Расшифровка и значение |
| --- | --- |
| Производственная сборка | Группировка компонентов в принятом определении изготовления; может отличаться от инженерного узла. |
| Фантомная сборка, phantom | Логическая группировка, раскрываемая при планировании по принятой политике; не обязательно самостоятельный учитываемый узел. |
| Расходный материал | Материал, потребляемый при выполнении работ, с определённой единицей и нормой. |
| Норма расхода | Плановое количество материала или компонента с определённой единицей, базой расчёта и условиями; отличается от фактического потребления. |
| Технологический процесс | Управляемое описание преобразования предмета производства. |
| Операция | Законченный участок работ в принятой организации процесса; детализация зависит от предприятия. |
| Переход | Более подробный элемент выполнения внутри принятой модели операции. |
| Производственный маршрут, routing | Организация прохождения производственных операций с последовательностями, вариантами и ресурсным контекстом. |
| Рабочий центр | Организационно-производственная группа возможностей или ресурсов для выполнения работ. |
| Оснастка | Приспособления и другие средства обеспечения конкретного производственного решения. |
| Ресурс | Оборудование, инструмент, оснастка, квалификация или другая необходимая возможность выполнения операции. |
| Норма времени | Плановая длительность с определённой базой расчёта: подготовка, штука, партия и другие составляющие. |
| Заготовка | Исходный или промежуточный предмет, из которого получают деталь последующими преобразованиями. |
| Установ | Принятое положение и закрепление предмета при обработке; влияет на подготовку и управляющие данные. |
| Припуск | Предусмотренный объём или слой материала для удаления при последующей обработке; относится к конкретному промежуточному состоянию. |
| Диспетчеризация производства | Назначение и координация выполнения работ с учётом доступности ресурсов и текущего производственного состояния. |
| Аддитивное производство | Получение объекта добавлением материала по подготовленному определению построения. |
| Электрофизическая обработка | Семейство способов обработки, использующих физические воздействия, отличные от обычного механического резания. |
| Термическая обработка | Управляемое воздействие температурным процессом для получения требуемого состояния материала. |
| Химико-термическая обработка | Процесс изменения состояния и состава поверхностной области при сочетании химического и температурного воздействия. |
| Метрология | Область измерений и обеспечения их достоверности, включая методы, средства и связанные основания пригодности. |
| Неразрушающий контроль | Оценка установленных признаков объекта методами, не предполагающими его разрушения. |
| Управляющая программа | Подготовленные команды для определённого оборудования и производственного контекста. |
| Постпроцессор | Средство преобразования подготовленных CAM-данных в целевое представление управляющей программы. |
| Расчётная сетка | Дискретное представление области для численного расчёта. |
| Решатель, solver | Программный компонент, реализующий выбранные численные методы для получения результата расчётной постановки. |
| Ассоциативность авторских данных | Управляемая зависимость, позволяющая отражать изменение источника в связанном объекте через обновление; не заменяет проверку пригодности результата. |
| Граничные условия | Условия взаимодействия расчётной модели с окружением и ограничения задачи. |
| Физический экземпляр | Индивидуальный материальный объект с собственной историей. |
| Серийный номер | Идентификатор отдельного экземпляра в установленной области уникальности. |
| Партия, lot/batch | Группа объектов, объединённая принятым основанием поставки, происхождения или изготовления. |
| Плавка | Идентифицируемое происхождение материала, связанное с конкретным производственным получением расплава и его учётом. |
| Генеалогия | История происхождения и преобразования материалов, партий и экземпляров. |
| Установка | Факт размещения компонента на позиции физического родителя в течение определённого периода. |
| As-designed | Проектная конфигурация изделия. |
| As-built | Фактически изготовленная конфигурация. |
| As-maintained | Конфигурация с учётом выполненного обслуживания, замен и доработок. |
| ПО | Программное обеспечение. Встроенное ПО работает в составе аппаратного изделия. |
| Прошивка, firmware | Программное содержимое, предназначенное для загрузки и работы в устройстве; термин требует уточнения состава и версии. |
| Программная сборка, build | Конкретный результат получения программного артефакта из исходных данных и окружения. |
| Загрузчик, bootloader | Компонент, обеспечивающий начальную загрузку и, в зависимости от реализации, обновление основного ПО устройства. |

Подробности: [техпроцессы](../course/14-process-and-routing/theory.md), [экземпляры](../course/15-physical-product-lifecycle/theory.md), [CAD/CAM/CAE](../course/16-cad-cam-cae-integration/theory.md).

## Администрирование, эксплуатация и интеграция

| Термин | Расшифровка и значение |
| --- | --- |
| Аутентификация | Установление идентичности обращающегося субъекта. |
| Авторизация | Проверка разрешения конкретного действия в заданном контексте. |
| ACL | Access Control List — список правил доступа к ресурсу или объекту. |
| RBAC | Role-Based Access Control — управление доступом на основе ролей. |
| ABAC | Attribute-Based Access Control — управление доступом по атрибутам субъекта, объекта, действия и, при необходимости, среды. |
| Сервисная учётная запись | Идентичность программного компонента с назначением, владельцем и ограниченными полномочиями. |
| Аудит | Регистрация значимых действий и оснований для последующего установления ответственности и истории. |
| Наблюдаемость, observability | Возможность объяснять состояние и поведение системы по журналам, метрикам и другим наблюдаемым данным. |
| Корреляция событий | Связывание технических записей общей операции по идентификаторам и контексту; в этом значении отличается от статистической корреляции признаков. |
| Метрика | Измеримый показатель с определённой областью, единицей и правилами расчёта. |
| Перцентиль | Значение границы распределения, ниже или на уровне которой находится заданная доля наблюдений по выбранной методике расчёта. |
| Корреляция | Наблюдаемая связь изменений или встречаемости признаков; сама по себе не доказывает причинного воздействия. |
| Индекс БД | Структура для ускорения определённых способов доступа к данным ценой хранения и обслуживания. |
| План выполнения | Выбранная СУБД последовательность операций получения результата запроса. |
| EXPLAIN | Средство PostgreSQL для просмотра плана запроса; режим с фактическим анализом выполняет запрос. |
| Селективность | Доля данных, отбираемая условием; влияет на целесообразность способа доступа. |
| Кэш | Сохранённый результат для повторного использования; требует корректного ключа контекста и правил актуальности. |
| RPO | Recovery Point Objective — целевая допустимая потеря данных, выраженная через время относительно точки сбоя. |
| RTO | Recovery Time Objective — целевое допустимое время восстановления. |
| Реплика | Дополнительное представление рабочего состояния, поддерживаемое переносом изменений; может воспроизвести ошибочное изменение и потому не заменяет резервную копию. |
| Архив | Организованное сохранение данных для длительного доступа по установленным правилам. Назначение отличается от оперативной реплики и восстановления после сбоя. |
| API | Application Programming Interface — программный интерфейс с определённым контрактом операций и данных. |
| REST | Representational State Transfer — архитектурный стиль взаимодействия распределённых систем; не синоним любого API. |
| Контракт данных | Согласованные структура, смысл, ограничения, версии и правила обработки передаваемых сведений. |
| Пагинация | Получение большого результата частями; требует правил порядка и стабильности выборки. |
| Идемпотентность | Отсутствие нового предметного эффекта при повторе одной логической операции. |
| Событие | Запись о совершившемся факте с идентичностью, временем и контекстом. |
| Команда | Запрос выполнить действие с предусловиями и возможностью отказа. Отличается от события, сообщающего уже совершившийся факт. |
| Причинный порядок | Последовательность, согласованная с зависимостями событий; не обязательно совпадает с порядком доставки или сортировкой часов разных систем. |
| Transactional outbox | Шаблон сохранения изменения и записи будущего события в одной локальной транзакции с отдельной доставкой. |
| Адаптер | Компонент согласования внешнего контракта и внутренней модели. |
| JVM | Java Virtual Machine — виртуальная машина для исполнения совместимого байт-кода. |
| Миграция | Перенос данных и их смысла между моделями или системами с управлением соответствиями и историей. |
| Профилирование | Исследование фактических свойств и качества исходных данных. |
| Происхождение данных, provenance | Сведения об источниках, преобразованиях и условиях получения результата. |
| Тестовый оракул | Независимый критерий ожидаемого результата проверки, а не повтор того же алгоритма. |

Подробности: [доступ](../course/03-administration-and-security/theory.md), [эксплуатация](../course/04-operations-and-performance/theory.md), [API](../course/17-apis-and-enterprise-integration/theory.md), [миграция](../course/18-migration-and-data-quality/theory.md), [проверка](../course/20-verification-and-testing/theory.md).
