# Реляционная модель PLM/PDM в PostgreSQL

[К теме «Предметная область и модель данных»](../README.md)

## Основная идея

Реляционное представление делает связи и ограничения явными. Разделение изделия и ревизии позволяет хранить устойчивое обозначение отдельно от изменяемого определения.

## Границы сущностей

Вхождение связывает ревизию родителя с дочерним определением либо с изделием, ревизию которого определит правило конфигурации. Семантика этих подходов различается. Документ связан с изделием отношением назначения; файловое представление не подменяет документ как управляемый объект.

## Технические последствия

Ключи и ограничения защищают локальную целостность. Исторические атрибуты и отношения требуют собственного правила версионирования. Хранение свойств в JSON не устраняет необходимость типов, единиц и валидации. Конкретные таблицы и SQL-схема будут определены на этапе практики; здесь фиксируется смысл будущих сущностей.
