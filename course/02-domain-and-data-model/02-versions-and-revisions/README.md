# Версии, итерации, ревизии и состояния

[К теме «Предметная область и модель данных»](../README.md)

## Основная идея

В курсе итерация — рабочее сохранение внутри ревизии; ревизия — контролируемый пересмотр определения; версия — общий термин, который без уточнения неоднозначен. Состояние отражает зрелость и разрешённые действия.

## Управление историей

Для выпущенного определения сохраняют состав, значимые атрибуты и связанные документы. Новое инженерное решение оформляют новой ревизией по принятой политике. Исправление служебной опечатки может иметь отдельный управляемый порядок, но не должно скрывать историю утверждённого определения.

## Пример

Ревизия A выпущена, B находится в работе. «Самая новая» B не обязательно разрешена к производству. Для ранее выпущенной сборки сохраняют использованную A или воспроизводимое правило её выбора. Порядок ревизий задаётся схемой ревизирования: сортировка строк не обязана соответствовать инженерной последовательности.

## Что именно сохраняется при новом пересмотре

Управляемый пересмотр должен сохранять исходное определение и формировать новый контекст изменения. При этом нужно решить, копируются ли состав, документы и свойства либо наследуются по правилам. Наследование, вычисляемое по текущим данным, способно изменить смысл уже выпущенного объекта; поэтому границы неизменности устанавливаются явно.

Итерация обычно позволяет продолжать работу над тем же намерением изменения. Ревизия отделяет контролируемые определения. Выбор нового обозначения связан с критерием идентичности и взаимозаменяемости, который устанавливает предприятие. Нельзя вывести этот выбор только из величины геометрического изменения.

## Независимость состояния и номера

B.3 может быть рабочим сохранением, A — действующим выпуском. В отчёте нужны обе оси: какая версия и в каком состоянии. Переход в «выпущено» не заменяет фиксацию проверенного содержимого. Иначе участник может согласовать B.2, а выпустить уже изменённую B.3 без повторной оценки.
