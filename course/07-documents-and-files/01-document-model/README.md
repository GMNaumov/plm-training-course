# Документы, наборы данных и связи с изделиями

[К теме «Управление документами и файлами»](../README.md)

## Основная идея

Документ имеет назначение и управляемую историю. Файл содержит байты, набор данных объединяет связанные ресурсы по принятой модели. Конкретное значение термина dataset зависит от продукта; в курсе это логическая группировка содержимого.

## Связи

Один документ может относиться к нескольким изделиям; у одного изделия бывают чертёж, спецификация и инструкция с разными ролями. Для обязательного основного документа задают кратность и допустимое состояние. Ссылка только на идентичность документа оставляет открытым вопрос выбора ревизии.

## Пример

Инструкция относится к семейству блоков, но отдельное приложение — к одному исполнению. Связь должна отражать область действия. Копирование одного файла в карточки всех блоков создаёт независимые копии и затрудняет изменение; управляемая общая ссылка сохраняет единый источник и позволяет выявлять затронутые изделия.

## Содержимое и назначение изменяются независимо

Один и тот же файл может быть приложен как справочный материал и как определяющий документ — последствия различаются. Управляемое отношение показывает, обязателен ли документ для выпуска и в какой области действует. Сам факт прикрепления не устанавливает его нормативную роль.

Документ также может иметь несколько представлений: исходное, доступное для просмотра, предназначенное для передачи. Роль представления не должна выводиться только из расширения. PDF способен быть исходным документом в одном процессе и производным результатом в другом.

## Версионирование комплекта

Если приложения меняются независимо, нужно определить, что фиксирует ревизия основного документа. Она может ссылаться на конкретные версии либо на другой принятый набор. Плавающее приложение способно изменить смысл ранее утверждённого комплекта. Поэтому граница выпуска включает значимые зависимости и правила их выбора, а не только текст главного файла.
