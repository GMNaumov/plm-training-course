# Зависимости CAD-сборок, метаданные и синхронизация EBOM

[К теме «Интеграция с CAD/CAM/CAE»](../README.md)

## Основная идея

CAD-сборка зависит от версий компонентов, внешних ссылок и настроек загрузки. Сохранить главный файл недостаточно, если остальные зависимости остаются плавающими.

## Синхронизация EBOM

Преобразование CAD-структуры требует правил включения: вспомогательная геометрия может исключаться, а негеометрические компоненты — добавляться из других источников. Количество, размещение и свойства передаются с известным владельцем. Обратные изменения требуют обработки конфликтов.

## Пример

Инженер перестроил CAD-сборку, а технологически значимое обозначение изменилось в PLM. Адаптер не должен выбирать победителя только по последней дате файла. Сначала определяют, где управляется каждый факт. Проверка сохранения охватывает полный набор зависимостей и сообщает, какие элементы не удалось зафиксировать или сопоставить.

## Структурное соответствие и исключения

При формировании EBOM из CAD задают правила для геометрических деталей, вспомогательных элементов, стандартных объектов и негеометрических компонентов. Ручное дополнение EBOM допустимо при известном владельце и сохранении основания. Повторная синхронизация не должна удалять такие элементы только потому, что их нет в CAD.

Для изменений количества нужно понимать, отражает ли авторская структура индивидуальные размещения или агрегированные строки. Один и тот же файл может участвовать несколькими размещениями с разными атрибутами.

## Конфликт изменений

Если свойство менялось с двух сторон, дата последней записи недостаточна. Устанавливают владельца поля и сравнивают изменения относительно общей исходной версии. Иначе поздняя служебная запись может затереть более раннее инженерное решение. Синхронизация сообщает о конфликте и сохраняет исходные данные до принятия решения, вместо молчаливого выбора победителя.
