# Нейтральные форматы обмена и границы адаптеров

[К теме «Интеграция с CAD/CAM/CAE»](../README.md)

## Основная идея

Нейтральный обмен переносит согласованную часть данных между инструментами. Формат — только один элемент контракта; необходимы правила идентификации, единиц, связей, версий и обработки потерь.

## Границы адаптера

Адаптер преобразует представление и вызывает разрешённые сервисы. Он не должен незаметно становиться владельцем инженерного решения. Неизвестные атрибуты, отсутствующие ссылки и неподдержанные элементы диагностируются, а не заполняются предположениями.

## Пример

После обмена геометрия визуально совпала, но потерялись атрибуты материала или связи с позициями. Успешное открытие файла не доказывает предметную полноту. Для конкретного формата и профиля заранее определяют, что обязано сохраниться, что передаётся отдельно и какие сведения признаются потерянными. Настоящая совместимость проверяется на выбранных версиях инструментов.

## Полнота и допустимые потери

Не каждый обмен обязан переносить все авторские свойства. Для просмотра достаточно одного набора, для дальнейшего редактирования — другого, для изготовления — третьего. Контракт должен определять обязательную семантику и разрешённые потери. Потеря допустимого справочного свойства отличается от потери единицы или определяющего атрибута.

Для структуры нужны устойчивые соответствия идентичностей и вхождений. Иначе повторный импорт создаст дубли либо ошибочно сопоставит одинаково названные компоненты.

## Двустороннее преобразование

Успешный экспорт и обратный импорт не гарантируют восстановление исходника: промежуточное представление могло не сохранять все сведения. Такой путь оценивается по заранее выбранным свойствам, а не только по возможности открыть файл. Адаптер сообщает о неподдержанных элементах и конфликте значений. Предметные решения о допустимости потери принимаются в соответствующей области ответственности и сохраняются вместе с результатом обмена.
