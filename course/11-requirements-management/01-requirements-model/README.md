# Типы, атрибуты, декомпозиция и версии требований

[К теме «Управление требованиями»](../README.md)

## Основная идея

Требование описывает необходимое свойство или ограничение, а проектное решение — способ его достижения. Смешение этих уровней ограничивает варианты реализации без явного основания.

## Структура

Кроме текста нужны источник, причина, владелец, область действия и критерий подтверждения. Для количественного условия определяют величину, предел, единицу и режим. Декомпозиция создаёт связанные требования, а не просто вложенные абзацы.

## Пример

«Обеспечить надёжное измерение» не задаёт проверяемого результата. Уточнение точности, диапазона и условий делает оценку возможной; конкретные значения в курсе не назначаются без согласованного объекта. При изменении текста создают управляемую ревизию и сохраняют связь с исходным источником и принявшим решение участником.
