# Распределение требований и связи с конструкцией

[К теме «Управление требованиями»](../README.md)

## Основная идея

Распределение назначает требование элементам реализации. Прослеживаемость сохраняет направленные отношения между источником, уточнениями, конструкцией и подтверждениями.

## Полнота покрытия

Требование может распределяться на несколько подсистем; одна подсистема — выполнять несколько требований. Подсчёт ссылок не показывает качество покрытия. Связь должна иметь роль: реализует, ограничивает, уточняет или подтверждает. Ревизия связанного объекта важна для интерпретации.

## Пример

Точность измерительного канала зависит от датчика, проводки, преобразователя и алгоритма. Ссылка только на датчик скрывает остальной вклад. Наличие связанных требований у каждого узла ещё не доказывает точность канала: нужна оценка совокупного результата в определённой конфигурации и условиях.

## Распределение без потери целого

Верхнее требование может выполняться совместно несколькими узлами. Связь «распределено на» показывает участие, но не объясняет, как складываются вклады. Для этого требуется архитектурное обоснование или модель характеристики. Простое создание одинакового текста у всех подсистем создаст дубли вместо распределения ответственности.

Нижнее требование также может поддерживать несколько верхних. Тогда изменение его предела затрагивает несколько целей. Направление и роль связей помогают не потерять такие зависимости.

## Проверка покрытия

Необходимо различать отсутствие реализации, отсутствие назначенного метода и отсутствие принятого свидетельства. Три пробела выглядят одинаково только в слишком общей матрице «есть ссылка». Отдельные роли связей позволяют видеть зрелость подтверждения. Если требование неприменимо выбранному исполнению, основание неприменимости также сохраняется, чтобы исключение из знаменателя отчёта было объяснимым.
