# Проверка составов, правил конфигурации и применяемости

[К теме «Проверка моделей и тестирование PLM/PDM-решений»](../README.md)

## Основная идея

Конфигурационные проверки оценивают не только наличие компонентов, но и основания их выбора. Важны правильная ревизия, допустимая применяемость, полнота опций и воспроизводимость.

## Граничные классы

Особенно значимы начало и конец интервала, перекрытие и разрыв, ноль и несколько кандидатов, неизвестный выбор и недоступная по правам зависимость. Свойства количества проверяют по путям, не устраняя допустимые повторы.

## Ожидаемое поведение

Недопустимая конфигурация должна давать объяснимый отказ или явно неполный результат по контракту. Молчаливый выбор первого кандидата маскирует ошибку. Для базовой линии важна устойчивость к последующему появлению новых ревизий: сохранённый результат не должен изменяться от обновления текущих данных. Конкретные тестовые наборы будут подготовлены вместе с практикой.

## Разные причины одинакового внешнего результата

Пустой список может означать законно пустую ветвь, отсутствие выбранной опции, невозможность выбрать ревизию или отсутствие доступа. Проверка только числа строк не различает эти ситуации. Ожидаемая диагностика является частью предметного результата.

При изменении времени или серии полезно рассматривать точки перехода, поскольку внутри интервала поведение может оставаться одинаковым. Для вариантов значимы не только отдельные значения, но и сочетания зависимостей между дисциплинами.

## Сохранённая конфигурация и новые данные

Зафиксированный набор должен сохранять прежний выбор при появлении новых ревизий. Динамический запрос может закономерно изменить результат. Проверка различает оба контракта и не требует от них одинакового поведения. Историческая воспроизводимость также предполагает доступность нужных документов и содержимого: сохранённые идентификаторы без восстанавливаемых объектов ещё не дают пригодной базовой линии.
