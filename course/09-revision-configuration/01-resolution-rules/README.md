# Выбор ревизий, состояния выпуска и приоритеты правил

[К теме «Конфигурирование по ревизионным правилам»](../README.md)

## Основная идея

Правило выбора определяет, какое управляемое определение допустимо использовать по ссылке. Его результат зависит от состояния данных и явно заданного порядка приоритетов.

## Учебная семантика

Сначала соблюдают зафиксированную ссылку, затем для плавающей ссылки находят кандидатов, проверяют допуск и применяют порядок. Если правило допускает предпочтение рабочей ревизии, это отдельный режим для разработки. Производственный режим не должен незаметно наследовать такой допуск.

## Пример

A выпущена, B согласуется, C находится в работе. Правило «последняя выпущенная» выбирает A; правило разработчика может выбрать C. Оба результата объяснимы при известном контексте. Ошибка возникает, когда название правила не раскрывает условия либо зависимый узел раскрывается с другим правилом без фиксации этого решения.

## Порядок применения условий

Пусть A и B выпущены, C находится в работе. Сначала определяется, разрешены ли рабочие состояния. Затем применяемость исключает определения, не относящиеся к серии. Только после этого порядок ревизий выбирает наиболее предпочтительное из допустимых. Если B новее, но не действует для серии, её новизна не имеет решающего значения.

Правило может учитывать специальное предпочтение проекта или рабочего контекста. Такое предпочтение требует явной области и не должно автоматически распространяться на производственный выпуск. Иначе один пользовательский режим начнёт менять смысл общего состава.

## Воспроизводимость правила

Название «для производства» недостаточно: содержание правила может измениться. Для исторического результата важны идентичность и версия определения правила, входной контекст и выбранные ревизии. Сохранение только имени восстанавливает намерение пользователя, но не обязательно прежний результат. Фиксация фактического выбора и объяснения устраняет эту неоднозначность.
