# Выбор ревизий, состояния выпуска и приоритеты правил

[К теме «Конфигурирование по ревизионным правилам»](../README.md)

## Основная идея

Правило выбора определяет, какое управляемое определение допустимо использовать по ссылке. Его результат зависит от состояния данных и явно заданного порядка приоритетов.

## Учебная семантика

Сначала соблюдают зафиксированную ссылку, затем для плавающей ссылки находят кандидатов, проверяют допуск и применяют порядок. Если правило допускает предпочтение рабочей ревизии, это отдельный режим для разработки. Производственный режим не должен незаметно наследовать такой допуск.

## Пример

A выпущена, B согласуется, C находится в работе. Правило «последняя выпущенная» выбирает A; правило разработчика может выбрать C. Оба результата объяснимы при известном контексте. Ошибка возникает, когда название правила не раскрывает условия либо зависимый узел раскрывается с другим правилом без фиксации этого решения.
