# Базовые линии, снимки и воспроизводимость конфигурации

[К теме «Конфигурирование по ревизионным правилам»](../README.md)

## Основная идея

Базовая линия — контролируемая фиксация набора определений для определённой цели. Снимок технически сохраняет состояние; статус базовой линии дополнительно подразумевает установленный порядок принятия и изменения.

## Полнота фиксации

Указывают корень, выбранные ревизии, существенные вхождения, документы, представления и контекст. Граница набора должна быть известна: базовая линия состава не обязательно содержит расчётную модель или программное окружение. Сохранённые ссылки должны вести к доступным историческим объектам.

## Пример

Испытание выполнено для корпуса B и блока управления A с определённой прошивкой. Фиксация только ревизии двигателя оставляет неопределёнными зависимости. Новая базовая линия после изменения не должна переписывать состав испытанного комплекта; между ними сохраняют различия и основание перехода.

## Состав базовой линии и её замыкание

Замыкание зависимостей — включение необходимых связанных определений до установленной границы. Для базовой линии конструкции это могут быть дочерние ревизии и определяющие документы; для расчётного обоснования — ещё постановка и исходные модели. Одна базовая линия не обязана охватывать всё предприятие, но её граница должна быть известна.

Если часть связей остаётся плавающей, набор может меняться при повторном чтении. Поэтому отделяют зафиксированное ядро от внешних ссылок, для которых гарантируется только наличие связи. Подобное различие важно при передаче и архивировании.

## Исправление после принятия

Найденная ошибка не является основанием незаметно заменить элемент уже принятой линии. Создают управляемое изменение, новую линию либо иной предусмотренный пересмотр с сохранением предыдущего состава. Это позволяет понять, по какому набору проводилось испытание и чем последующее решение от него отличается.
