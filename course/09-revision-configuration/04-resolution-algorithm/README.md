# Алгоритм разрешения состава и диагностика неоднозначностей

[К теме «Конфигурирование по ревизионным правилам»](../README.md)

## Основная идея

Разрешение состава — вычисление конкретной конфигурации из структуры и правил. Результат включает выбранные определения и объяснение выбора, а не только список строк.

## Последовательность рассуждения

Для корня фиксируют контекст; для каждого вхождения определяют участие и способ ссылки; кандидатов фильтруют и упорядочивают; выбранную ревизию раскрывают дальше. Сохраняют путь, причину выбора и признаки неполноты. Контроль циклов выполняют по текущему пути.

## Диагностика

Ноль кандидатов означает отсутствие допустимого определения. Несколько равноприоритетных кандидатов означают неоднозначность. Недостаток прав означает неполноту видимости, а не отсутствие данных. Отчёт должен различать эти состояния. Для исторической воспроизводимости фиксируют также версию правила и исходный контекст; повторный запуск по текущим данным может дать другой результат.

## Причины отказа на уровне вхождения

Неудача разрешения должна сохранять место возникновения. «Нет ревизии датчика» может относиться только к одному пути с особой применяемостью, тогда как тот же объект в другой ветви выбирается успешно. Глобальное сообщение по обозначению теряет эту разницу.

Полезно различать ошибку определения правила, неполноту параметров, отсутствие допустимых данных и ограничение видимости. Для каждого случая следующий шаг иной: уточнение запроса, исправление модели, выпуск определения либо обращение к ответственному за доступ.

## Устойчивость вычисления

Если раскрытие состоит из нескольких запросов, параллельный выпуск дочерней ревизии способен изменить кандидатов между шагами. Результат может объединить разные моменты данных. Поэтому выбирают согласованный снимок, зафиксированный набор либо другой явно описанный механизм. Фиксация только времени начала операции не обеспечивает согласованность автоматически: она должна использоваться правилами чтения и выбора.
