# Постановка задачи и модель данных изделия

[К теме «Итоговый сквозной проект»](../README.md)

## Основная идея

Постановка PLM-задачи начинается с вопроса предприятия и границ ответственности. Сначала определяют, какие решения и факты должны быть управляемыми, затем выбирают объекты и механизмы.

## Целостность модели

Модель связывает идентичности изделий, ревизии, вхождения, документы, процессы, экземпляры и свидетельства. У каждого факта есть владелец, временной смысл и источник. У каждого отношения — назначение и ограничения. Необязательно помещать все области в одну систему, но границы обмена должны быть явными.

## Границы этапа

Сквозной контекст авиационного двигателестроения уже определён. Точный перечень узлов и обязательные атрибуты пока не утверждены. Настоящая практическая постановка должна будет закрепить эти решения; этот раздел объясняет подход и не задаёт будущему учащемуся задания или скрытого эталонного решения.

## Предметная граница решения

Модель должна отвечать на выбранные вопросы, сохраняя нужную глубину. Если цель — проследить источник материала до экземпляра, одной типовой BOM недостаточно. Если цель — управлять выпусками документов, полная диспетчеризация станков может лежать за границей. Явный охват предотвращает обещание функций, для которых не определены данные и ответственность.

Сущности выбираются по независимости идентичности, состояния и изменения. Отношения — по смыслу вопросов. Техническое удобство одной таблицы не отменяет различия ревизии, вхождения и установки.

## Допущения модели

Неизвестный факт может временно задаваться условным соглашением, но соглашение обозначается и не выдаётся за отраслевую норму. Например, учебный порядок ревизий или формат серии достаточен для объяснения алгоритма. Перед практикой он должен стать согласованной частью демонстрационного контекста. Сейчас теория формирует язык таких решений, не назначая скрытой обязательной реализации.
