# Планы запросов, индексы и производительность больших составов

[К теме «Эксплуатация, надёжность и производительность»](../README.md)

## Основная идея

Оптимизация начинается с операции и её плана выполнения. Для BOM это поиск вхождений, выбор ревизий, рекурсивный обход и агрегирование.

## Источники затрат

Индексы на направлениях обхода и условиях фильтрации сокращают чтение подходящих строк. Полезность зависит от селективности и статистики. Запрос атрибутов отдельно для каждой позиции увеличивает число обращений и часто дороже обхода.

## Корректность

Преждевременное устранение повторных вхождений искажает количества: общая деталь даёт вклад по нескольким путям. Кэш должен учитывать ревизию, правила, опции, применяемость и доступ. План с фактическим выполнением анализируют в подходящей среде, понимая, что измеряемый запрос действительно исполнится.

Механизм чтения плана и режим фактического выполнения описаны в [PostgreSQL 18: Using EXPLAIN](https://www.postgresql.org/docs/18/using-explain.html); назначение и ограничения индексов — в [PostgreSQL 18: Indexes](https://www.postgresql.org/docs/18/indexes.html). Версия локальной учебной базы ещё не определена.
