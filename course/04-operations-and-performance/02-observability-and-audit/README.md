# Журналы, метрики, диагностика и аудит

[К теме «Эксплуатация, надёжность и производительность»](../README.md)

## Основная идея

Наблюдаемость позволяет восстановить ход операции по измеримым признакам. Для PLM значимы время раскрытия состава, задержка публикации, доля отказов выпуска и возраст заданий в очереди.

## Журнал и аудит

Журнал описывает выполнение программы. Аудит отвечает, кто, когда, над каким объектом и на каком основании действовал. Записи связывают с операцией и версией; секреты и лишние персональные сведения исключают.

## Интерпретация

Рост отказов выпуска означает либо сбой, либо нормальное обнаружение неполных данных. Среднее время скрывает редкие длительные операции: анализируют распределение и тяжёлые сценарии. Для событий разных систем учитывают часы, задержки доставки и различие времени совершения и регистрации.

## Корреляция событий

Идентификатор операции объединяет пользовательский запрос, прикладные действия, фоновые задания и внешний обмен. Без него одинаковые сообщения об ошибке в разных журналах трудно связать с одним действием. Идентификатор объекта и его версии дополняет эту связь предметным контекстом.

Метрика показывает масштаб, журнал — детали, аудит — значимое действие и исполнителя. Сохранение одной категории не заменяет остальные. Число ошибок без общего числа запросов также плохо интерпретируется: десять отказов из ста и из миллиона означают разные ситуации.

## Задержка как распределение

Среднее значение скрывает редкие тяжёлые запросы. Перцентиль — граница, ниже которой находится заданная доля наблюдений; например, 95-й описывает время для большинства, но не всех операций. Сравнивать показатели нужно при сходном составе нагрузки. Изменение среднего после исключения самых тяжёлых BOM ещё не доказывает ускорения системы.
