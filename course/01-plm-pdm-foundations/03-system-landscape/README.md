# Место PLM/PDM среди CAD, ERP, MES и других систем

[К теме «Основы PLM/PDM и жизненный цикл изделия»](../README.md)

## Основная идея

Расположение функции определяется архитектурой предприятия. Исходная граница: PLM управляет утверждённым определением изделия и подготовкой изменений; ERP — планированием и хозяйственным учётом; MES — ходом выполнения производственных операций.

## Владение и обмен

Для каждой сущности задают систему-владельца, получателей, момент публикации и правила обратной связи. Обозначение детали может приходить из PLM, закупочный статус — из ERP, факт установки компонента — из системы исполнения. Отдельные атрибуты одного объекта могут иметь разных владельцев.

## Риск интеграции

Двунаправленная синхронизация без правил конфликтов создаёт конкурирующие источники истины. Успешная передача сообщения ещё не означает применения данных. Различают отправку, приём, предметную обработку и подтверждение результата. CAD, CAM и CAE включаются в ландшафт как авторские и расчётные инструменты с собственными зависимостями.

## Разделение данных по смыслу

Одно слово «деталь» скрывает несколько наборов сведений. Конструкторское обозначение и определение задают, что разрешено изготавливать. Закупочный источник определяет, откуда можно получить компонент. Складской остаток показывает доступное количество. Фактическая установка указывает, какой объект использован. Назначение владельца каждого набора предотвращает конфликт одинаковых полей в разных системах.

## Четыре вопроса к границе обмена

Для передачи нужно знать исходный факт, момент готовности, принимаемый результат и способ подтверждения. Например, выпуск MBOM является основанием передачи, но ERP может отклонить пакет из-за неизвестной единицы. Факт выпуска остаётся действительным, а факт применения в ERP ещё отсутствует.

Обратное сообщение должно отражать именно результат: принято к обработке, применено либо отклонено с причиной. Соединение без такой семантики передаёт байты, но оставляет участникам разные представления о состоянии работы. Эти различия становятся особенно заметны после сбоя и повторной отправки.
