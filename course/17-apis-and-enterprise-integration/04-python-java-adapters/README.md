# Адаптеры и прикладная логика на Python и Java

[К теме «API, расширения и интеграция предприятия»](../README.md)

## Основная идея

Адаптер отделяет внешний контракт от внутренней модели. Прикладная логика выполняет правила предприятия; транспортный код обеспечивает передачу и техническую обработку.

## Ответственность компонентов

Преобразование единиц, сопоставление идентификаторов и проверка полноты должны быть явными. Инварианты выпуска и доступа не стоит дублировать несовместимыми реализациями во всех клиентах. Секреты и адреса окружений отделяют от кода, журналы связывают с идентификатором операции.

## Границы этапа

В будущей учебной реализации Python предполагается для пакетных преобразований и анализа, Java — для сервисных операций. Оба языка могут решать и другие задачи. Конкретные библиотеки, версии JVM, способ запуска и подключения пока не выбраны. Код адаптеров, установка пакетов и настройка сервисов на этом этапе не выполняются.

## Где заканчивается преобразование

Адаптер переводит формат и идентичности, но не должен произвольно решать, допустима ли замена или готов ли объект к выпуску. Такие решения относятся к предметным операциям с определёнными полномочиями. Это позволяет использовать одинаковые правила для интерфейса пользователя, пакетной загрузки и интеграции.

Если преобразование неоднозначно, исходная запись сохраняется с причиной отказа. Подстановка ближайшего значения может скрыть потерю смысла. Важно отличать исправление формата от нового инженерного решения.

## Работа пакетами

Для большого обмена определяют границу атомарности: весь пакет, независимый объект или связанная группа. Частичный успех требует отчёта о применённой области и безопасного продолжения. Язык реализации не задаёт эту семантику. Python и Java могут участвовать в разных слоях, но контракт операции, обработка версий и сохранение происхождения остаются общими архитектурными обязанностями.
