# Сервисная модель, API и контракты данных

[К теме «API, расширения и интеграция предприятия»](../README.md)

## Основная идея

Сервисный контракт описывает действие над предметной моделью. Он включает идентификаторы, версии, единицы, обязательность полей, предусловия и различимые результаты ошибок.

## Семантика операции

Создание, изменение и выпуск имеют разные полномочия. Для изменения полезна ожидаемая версия: несовпадение сообщает о конкурентном редактировании. Для списочных методов нужны правила пагинации и стабильности среза; несколько страниц текущих данных не обязательно образуют один исторический снимок.

## Пример

Получатель получает количество 10 без единицы и контекста. Синтаксис корректен, предметный смысл неизвестен. Совместимость контрактов требует не только сохранения поля, но и неизменности его значения. Документация конкретного API и авторизация будут выбраны на этапе практики; здесь нет вымышленных конечных точек или обещаний поддержки определённых продуктов.
