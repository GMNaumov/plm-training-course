# События, идемпотентность, повторы и обработка ошибок

[К теме «API, расширения и интеграция предприятия»](../README.md)

## Основная идея

Надёжность обмена строится из сохранения факта, повторяемой доставки и контролируемого применения. Отсутствие ошибки отправки не доказывает завершения всей цепочки.

## Идемпотентность и outbox

Шаблон transactional outbox сохраняет исходное изменение и запись о будущем событии в одной локальной транзакции. Отдельный обработчик доставляет событие; потребитель всё равно должен выдерживать дубликаты. Ключ операции связывают с содержимым, чтобы случайное повторное использование ключа с другим запросом обнаруживалось.

## Ошибки и порядок

Временные сбои допускают ограниченные повторы с увеличением пауз. Некорректные данные требуют исправления либо разбирательства. Для сообщений вне порядка сравнивают версии и ожидаемые зависимости. Невосстановленные ошибки остаются видимыми и имеют владельца; бесконечный автоматический повтор не является разрешением проблемы.
