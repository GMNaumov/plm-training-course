# Аппаратная конфигурация, встроенное ПО и прошивки

[К теме физических экземпляров изделия](../README.md)

## Основная идея

Аппаратно-программная конфигурация связывает ревизии электроники, разрешённые выпуски ПО и фактическую загрузку на экземпляр. Название продукта или ветки разработки недостаточно для воспроизводимости.

## Идентификация

Для программного результата сохраняют идентичность сборки, происхождение и контрольную сумму; для установки — устройство, событие, результат и основание допуска. Совместимость может зависеть от загрузчика, аппаратного исполнения и настроечных данных.

## Пример

Два блока одной модели имеют разные аппаратные ревизии. Новая прошивка разрешена только для одной. Команда «обновить до последней» без проверки сочетания нарушает конфигурационный контроль. Возврат прежнего ПО также требует разрешённого пути и фиксации события. Курс рассматривает модель управления; конкретные процедуры квалификации аппаратуры и ПО не назначаются.

## Код, программный результат и загрузка

Идентификатор исходной версии показывает, из каких данных получено ПО. Идентификатор сборки уточняет конкретный программный результат. Контрольная сумма определяет байты. Событие загрузки связывает результат с устройством и моментом. Эти сведения дополняют друг друга: одинаковый исходный текст не обязательно даёт одинаковый двоичный результат при другом окружении.

Настроечные данные могут изменять поведение без смены основного образа. Если они влияют на разрешённую функцию, их идентичность и область применения также входят в конфигурацию.

## Совместимость и возврат

Разрешённое сочетание включает аппаратную ревизию, загрузчик, основной образ и значимые настройки. Обновление одного элемента требует проверки ограничений. Возврат к прежней версии не становится безопасным только потому, что она когда-то работала: состояние данных или аппаратуры могло измениться. Факт попытки, результат и применённое основание сохраняются независимо от успеха операции.
