# Порядок загрузки, связи, повторный запуск и сверка

[К теме «Миграция и качество данных»](../README.md)

## Основная идея

Загрузка следует графу зависимостей и сохраняет устойчивое соответствие идентификаторов. Пакет и состояние его обработки позволяют понимать частичный результат.

## Повторяемость

Перед повтором различают уже созданный объект, созданную ревизию и сохранённую связь. Один общий признак «строка загружена» может быть недостаточен. Ошибки не должны исчезать при перезапуске, а успешные записи — дублироваться.

## Сверка

Контрольные суммы проверяют содержимое файлов; количества — объём переноса; предметные выборки — смысл. Для состава важны направления, количества, единицы и выбранные ревизии. Если источник продолжает изменяться, определяют границу снимка и правила переноса последующих изменений. Иначе две формально успешные выгрузки могут описывать разные моменты и давать несогласованную цель.

## Зависимости и промежуточные состояния

Связи загружаются после появления необходимых идентичностей либо через явно разрешённые промежуточные ссылки. В последнем случае незавершённость не должна выглядеть рабочей корректной моделью. Завершение этапа подтверждает закрытие обязательных зависимостей.

Если загрузка остановилась после создания ревизий, но до файлов, повтор продолжает с известного состояния. Ключ соответствия определяет уже перенесённые объекты; номер строки временного файла для этого ненадёжен, поскольку порядок выгрузки может измениться.

## Возврат и исправляющий перенос

После начала работы в цели простое удаление загруженных объектов может уничтожить новые связи пользователей. Поэтому способ исправления зависит от момента: до приёмки возможен повтор из чистого состояния, после — управляемое корректирующее преобразование. План переключения и граница владения данными должны учитывать этот переход. Техническая обратимость импорта не равна обратимости последующих бизнес-действий.

## Повтор неизменного пакета и конкурентные загрузчики

L14 проверяет повтор одного неизменяемого снимка. Два независимых загрузчика могут одновременно не обнаружить конфликт и затем конкурировать за вставку. ON CONFLICT DO NOTHING устраняет ошибку уникальности, но не доказывает одинаковый смысл пропущенных данных. Для конкурентного режима нужна координация проверки и эффекта с повторной оценкой после ожидания.

Версия преобразования также входит в происхождение. Исправление mass-v1 не должно незаметно превратить старую запись в результат mass-v2. Новый пакет сохраняет различия и основание принятия. Область источника нужна дополнительно к source_id, если одинаковые локальные ключи поступают из разных систем.
