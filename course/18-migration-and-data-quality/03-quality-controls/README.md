# Проверки полноты, целостности и бизнес-правил

[К теме «Миграция и качество данных»](../README.md)

## Основная идея

Качество оценивают по явно заданным правилам и области данных. Полнота означает наличие необходимых сведений; целостность — допустимость связей; корректность — соответствие смыслу и ограничениям.

## Уровни проверки

Синтаксический уровень обнаруживает неверные типы. Структурный — отсутствующие ссылки и циклы. Предметный — недопустимые состояния, размерности и несовместимые конфигурации. Процессный — отсутствие основания выпуска или владельца. Эти уровни дополняют друг друга.

## Пример

Карточка имеет заполненное поле материала, но значение относится к снятой с применения спецификации. Формальная полнота высокая, пригодность для нового выпуска сомнительна. Показатель качества должен иметь знаменатель, период и правило отбора; устранение неудобных объектов из отчёта не является улучшением данных.

## Качество относительно действия

Данные могут быть достаточны для справочного поиска и недостаточны для выпуска. Поэтому правила качества связываются с назначением и состоянием. Объект с неизвестной характеристикой не обязательно удаляется, но не должен проходить действие, для которого она обязательна.

Нарушение может быть локальным, структурным или временным. Заполненное количество корректного типа ещё может использовать неверную единицу; существующая ссылка — вести к неподходящей ревизии; допустимый интервал — конфликтовать с соседним. Проверки рассматривают сочетания фактов.

## Ответственность за устранение

Технический отчёт должен показывать объект, правило, обнаруженный факт и область влияния. Владелец решает, исправить источник, изменить преобразование или принять обоснованное исключение. Показатель качества учитывает такие исходы явно. Перенос дефектов в отдельный скрытый список без отражения в общей области не повышает фактическую готовность данных к работе.
