# Семейства изделий, признаки, опции и значения

[К теме «Конфигурирование по опциям и вариантам»](../README.md)

## Основная идея

Семейство объединяет изделия с общими решениями и управляемыми различиями. Признак описывает изменяемое свойство, домен — множество допустимых значений, выбор — конфигурацию конкретного запроса.

## Полнота выбора

Для обязательного признака должно быть задано значение. Множественный выбор требует ограничений количества и совместимости. Значение по умолчанию — правило заполнения, а не доказательство пригодности. Незаданный параметр полезен в предварительном поиске, но не всегда допустим при выпуске.

## Пример

Признак «каналы управления» принимает значения «один» и «два». Признак «комплект датчиков» зависит от него. Отдельные коммерческие названия исполнений можно связать с набором признаков; копирование названий в каждую позицию состава делает общую модель вариантов трудно проверяемой.

## Признак, значение и пакет выбора

Признак «тип интерфейса» имеет домен значений; конкретная конфигурация выбирает одно из них. Пакет опций может объединять несколько согласованных выборов для удобства. Тогда он не становится независимым инженерным фактом: необходимо определить, раскрывается ли пакет в признаки и допускается ли их дальнейшее изменение.

Версия модели семейства задаёт доступные признаки и значения. Выбор, сделанный по старой модели, нельзя интерпретировать исключительно по текущему каталогу: значение могло быть переименовано, разделено или снято с нового использования.

## Техническая и заказная конфигурация

Заказчик может указывать желаемую функцию без конкретного компонента. Инженерное правило переводит её в решения и ограничения. Смешение этих уровней делает каждую замену компонента изменением коммерческого предложения. Разделение позволяет сохранить функцию и управляемо пересмотреть её реализацию, с проверкой совместимости и применяемости новой конструкции.
