# Междисциплинарные варианты механики, электрики, электроники и ПО

[К теме конфигурирования по опциям](../README.md)

## Основная идея

Вариант изделия пересекает границы механики, электрики, электроники и ПО. Общий признак должен согласованно изменять все связанные определения и интерфейсы.

## Интерфейсные зависимости

Совместимость включает геометрическое сопряжение, питание, распиновку, протокол, функции и разрешённые версии ПО. Связи совместимости версионируют; общее имя семейства не подтверждает сочетание конкретных ревизий.

## Пример

Дополнительный канал измерения требует места крепления, датчика, контактов жгута, входа блока и поддержки прошивкой. Каждый компонент может быть выпущен отдельно, но комплект — ещё не подтверждён. Поэтому совместимость оценивают для конфигурации и связывают с результатами проверок. При изменении одного интерфейса анализ охватывает всех его участников.

## Совместимость как многоместное отношение

Иногда недостаточно попарных разрешений. Датчик совместим со жгутом, жгут — с блоком, но требуемая функция доступна только при определённой прошивке и аппаратной ревизии одновременно. Значит, область разрешения относится к сочетанию нескольких участников.

Описание интерфейса должно включать то, что действительно ограничивает совместимость: сопряжение, электрические свойства, обмен данными, функциональные ожидания и версии. Наличие разъёма того же семейства не покрывает весь интерфейс.

## Управление междисциплинарным изменением

При смене одного участника владелец изменения определяет затронутые соглашения и подтверждения. Разные подразделения оценивают свою часть, итог принимается для целого сочетания. Связи между дисциплинами должны вести к конкретным определениям или воспроизводимым правилам. Общая ссылка «электрика согласована» не показывает, какие версии участвовали в принятом решении.
