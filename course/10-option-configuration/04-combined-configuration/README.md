# Совместное применение опций, ревизионных правил и применяемости

[К теме «Конфигурирование по опциям и вариантам»](../README.md)

## Основная идея

Опции отвечают, какие решения нужны, применяемость — где они действуют, ревизионные правила — какое определение выбрать. Каждое измерение сохраняет собственный смысл.

## Контекст результата

Для воспроизводимости фиксируют корневое определение, выбор признаков, дату или серию, версию правил и выбранные зависимости. Ключ кэша или отчёта, содержащий только набор опций, может смешать разные инженерные конфигурации.

## Пример

Вариант с резервированием разрешён правилами семейства, но новая ревизия блока выпущена только для поздней серии. Для раннего экземпляра такой выбор может оказаться неразрешимым. Нельзя автоматически брать рабочую ревизию или отключать ограничение применяемости. Корректный результат — объяснимое отсутствие допустимого определения с указанием конфликтующего условия.

## Контроль согласованности измерений

Ревизионные и вариантные условия могут противоречить друг другу косвенно. Выбранная опция требует компонент B, но B разрешён только для поздней серии; запрос относится к ранней. Логическая допустимость опции остаётся истинной, но полная конфигурация не разрешается. Диагностика должна показать эту цепочку, а не только имя отсутствующего компонента.

Разные определения могут использовать дату заказа, изготовления или события обслуживания. Эти даты не взаимозаменяемы. Для каждого правила указывается, какое время входит в контекст.

## Фиксация результата

При сохранении выбранного исполнения фиксируют версию модели признаков, выбор значений, корень и правила разрешения. При необходимости отдельно сохраняют конкретные дочерние ревизии и документы. Так можно воспроизвести как намерение выбора, так и фактический результат. Сохранённое намерение полезно для пересчёта по новым правилам, но такой пересчёт является новым решением и не переписывает прежнюю конфигурацию.
