# Права доступа, наследование и проверка полномочий

[К теме «Администрирование, модель доступа и расширение системы»](../README.md)

## Основная идея

Разрешение вычисляется для действия над объектом с учётом субъекта и контекста. Чтение метаданных, просмотр представления, скачивание исходника, изменение состава и выпуск ревизии — разные действия.

## Наследование и проверка

ACL задаёт правила доступа к объектам, RBAC — разрешения ролей, ABAC — условия на атрибуты. Они могут сочетаться. Приоритет запрета не переносится между продуктами без проверки. Исходный принцип курса — разрешать только предусмотренные действия.

## Граничный случай

Пользователь видит сборку, но не имеет прав на компонент. Система должна сохранять безопасность и сообщать о неполноте в допустимой форме. Скрытый объект нельзя молча интерпретировать как отсутствующий в составе. Те же правила действуют для отчётов, API и публикации файлов.

## Разрешение через несколько путей доступа

Один документ доступен через карточку изделия, поиск, прямую ссылку, отчёт и экспорт. Политика должна описывать результат действия, а не только экран. Если разрешено видеть обозначение, но запрещён исходный CAD-файл, эти возможности проверяются отдельно. Производное представление может содержать те же чувствительные сведения.

Право на изменение объекта также не означает право на его выпуск или изменение состава связанной сборки. Иначе делегирование узкой работы создаёт непреднамеренную ответственность за более широкое решение.

## Достоверность неполного результата

Пусть пользователь видит девять из десяти компонентов. Сводная масса по девяти позициям не должна маркироваться как масса всей сборки. Система может ограничить отчёт или показать разрешённый признак неполноты. Конкретная форма сообщения не должна раскрывать защищённые сведения. Так безопасность и корректность отчёта рассматриваются совместно, без молчаливой подмены скрытого нулём.
