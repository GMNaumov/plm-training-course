# Администрирование типов, атрибутов, связей и правил

[К теме «Администрирование, модель доступа и расширение системы»](../README.md)

## Основная идея

Расширение схемы начинается с предметного смысла: какой факт хранится, кто его задаёт и когда он обязателен. Создание поля без этих решений переносит неопределённость в данные.

## Элементы конфигурации

Для атрибута задают тип, кратность, единицу, источник и правила изменения. Для связи — типы концов, направление и обязательность. Для типа объекта — наследуемые свойства и отличающие правила. Классификационный признак не обязательно требует нового системного типа.

## Эволюция модели

Новый обязательный атрибут затрагивает существующие записи, импорт, API и отчёты. Нужна политика заполнения старых данных. Удаление значения справочника может нарушить историю: часто прекращают новый выбор, сохраняя старые ссылки. Настройка интерфейса проверяется отдельно от серверных ограничений.
