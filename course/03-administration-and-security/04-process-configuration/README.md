# Настройка жизненных циклов и процессов согласования

[К теме «Администрирование, модель доступа и расширение системы»](../README.md)

## Основная идея

Жизненный цикл определяет состояния и переходы. Поток согласования организует задачи, решения и исполнение переходов. Один цикл может использовать несколько процессов для разных документов.

## Настраиваемые правила

Переход имеет исходное состояние, условие, полномочие и результат. Задача — исполнителя, входные материалы и варианты решения. Автоматический обработчик проверяет те же предметные ограничения, что и ручное действие.

## Пример

Выпуск расчёта требует проверенного набора исходных данных и одобрения расчётчика. Завершение задач не гарантирует условий, если исходная модель изменилась. Перед переходом повторно проверяют версии и полноту. При отказе сохраняют причину и маршрут возврата, а не стирают историю решений.

## Согласование фиксированного набора

Участник принимает решение по определённым данным. Если объект редактируется во время согласования, нужно знать, какие изменения делают прежнее решение недействительным. Простая привязка задачи к устойчивой карточке не отвечает на этот вопрос.

Учебная модель рассматривает контролируемый набор: ревизию, значимые зависимости и проверяемые параметры. При существенном изменении набор переоценивается либо создаётся новый цикл согласования. Служебное изменение отображения может иметь другую политику, но граница должна быть установлена заранее.

## Настройка маршрута и предметных условий

Маршрут отвечает, кто и в каком порядке рассматривает материалы. Условие выпуска отвечает, что должно быть истинно перед переходом. Разделение полезно, когда разные подразделения используют разные маршруты, но единые правила полноты. Обработчик перехода остаётся последней предметной проверкой, а не доверяет одному факту завершения пользовательских задач.
