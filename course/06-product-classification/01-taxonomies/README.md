# Классы, иерархии и классификационные схемы

[К теме «Классификация изделий и компонентная база»](../README.md)

## Основная идея

Таксономия — система классов с определёнными основаниями группировки. Иерархия помогает наследовать общие признаки, но её глубина должна соответствовать различиям, полезным при поиске и выборе.

## Границы классификации

Объект может принадлежать нескольким независимым классификационным схемам: функциональной, закупочной, технологической. Это не означает нескольких физических изделий. Место в BOM и принадлежность к проекту меняются независимо от класса.

## Эволюция

Разделение класса требует правил переноса объектов и сопоставления атрибутов. Удаление класса не должно оставлять записи без объяснимой истории. Например, общий класс датчиков можно разделить по измеряемой величине, сохранив исходные идентификаторы изделий. Новую схему сначала сопоставляют с существующими данными и поисковыми сценариями.

## Дерево классов и многомерное описание

Иерархия удобна для отношений общего и частного: датчик → датчик давления. Изготовитель, диапазон и электрический интерфейс могут быть независимыми измерениями. Создание отдельного класса для каждого их сочетания делает один и тот же смысл многократно повторяемым.

Многомерное описание позволяет искать по нескольким признакам, не меняя принадлежность к базовому классу. При этом наследуемые свойства должны сохранять совместимый смысл. Дочерний класс может уточнять ограничения, но не должен незаметно переопределять единицу или трактовку общего атрибута.

## Перенос между схемами

При объединении классификаторов важны соответствия классов и признаков, а не только перевод названий. Один класс старой схемы может разделиться на несколько новых; несколько старых — объединиться. Объекты с недостаточными характеристиками остаются неразрешёнными до уточнения. Присвоение ближайшего класса по тексту без проверки переносит неопределённость в результаты поиска.
