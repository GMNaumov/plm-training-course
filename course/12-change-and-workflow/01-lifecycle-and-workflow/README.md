# Состояния объектов, переходы и потоки согласования

[К теме «Управление изменениями и процессами согласования»](../README.md)

## Основная идея

Состояние характеризует объект; workflow характеризует выполнение процесса. Объект может оставаться «на согласовании», пока процесс проходит несколько параллельных проверок.

## Переходы

У перехода есть условия, полномочия и последствия. Завершение задач даёт основание попытаться выполнить переход, но сервер повторно проверяет актуальность данных. Параллельные ветви требуют правила объединения: все решения, большинство либо отдельное ответственное решение — это разные модели.

## Пример

Чертёж согласован, но связанная спецификация изменилась после проверки. Автоматический выпуск должен обнаружить изменение контролируемого набора. Возврат на доработку сохраняет решения предыдущего цикла и создаёт новые задачи по установленной политике. Нельзя получить корректную историю простым обнулением списка подписей.

## Состояние процесса и состояние объекта

Процесс может ожидать внешнего подтверждения, тогда как документ остаётся выпущенным в прежней ревизии. Новый процесс согласования не должен переводить исторический выпуск в рабочее состояние без предметного основания. Иначе начало подготовки изменения внезапно лишит производство действующего определения.

Переходы состояния могут требовать полномочий, полноты и актуального решения. Workflow организует получение решения, но серверная операция перехода проверяет условия в момент фиксации.

## Повторный цикл рассмотрения

После возврата на доработку определяется, какие участники должны рассмотреть изменённый набор. Полный повтор и частичное повторное согласование имеют разную стоимость и основания. История сохраняет, кто рассматривал каждую итерацию. Один вечный флаг «одобрено» без версии не позволяет отличить действующее решение от решения по прежнему содержимому.
